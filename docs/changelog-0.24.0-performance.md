# Exact-release benchmark comparison

Measured on 2026-11-05 America/Los_Angeles after publication. Lower `baml-language-0.23.0` = `f0f0bb5135bba599c11a32cc4d631f2f66f1f96f`; upper `baml-language-0.24.0` = `dec4713a0e7c9699442bf5855b4f327063f769c5`. Used published macOS arm64 CLI/CFFI artifacts and matching PyPI wheels. Python 3.12.0, Apple M3 Max, 96GiB RAM, macOS 26.6.2(25G83), arm64. Release Rust profile: opt-level 3, fatLTO, codegen-units 1; artifact workflows build bridge_cffi with cargo --release and Python wheel with maturin --release --strip. SDK bytecode uses CLI default O2; these are interpreter measurements, not native Rust backend measurements.

Method: identical BAML workload source generated separately by each fixed release compiler. Every fresh Python process initialized the generated SDK before timing. Every BAML workload was warmed once, then one complete call measured with time.perf_counter_ns. Five interleaved lower/upper process pairs; order alternated by pair. No CPU pinning (macOS). Local machine also ran the changelog workflow, so control rows with noisy ranges are not proof of a small gain. Each measured result matched its warmup and the lower/upper outputs agreed. SDK telemetry was explicitly disabled by `[bridge.env_var_names] BAML_TELEMETRY = "BAML_TELEMETRY"` and environment BAML_TELEMETRY=off. BOUNDARY_API_KEY=local and separate BAML_HOME were set; no recording directories were created.

BAML workloads were copied verbatim from pinned source `baml_language/tools/speedtest/workloads` with only entrypoint names changed (and enum workload helper `advance` renamed to avoid collision with nbody). Source paths: string/template-request-line-10k/main.baml; string/join-request-line-10k/main.baml; interfaces/enum-equals-100k/main.baml; compute/nbody-20k/main.baml. Timings include one Python bridge boundary plus the entire BAML kernel, excluding startup/initialization and generation/compilation. No-op workload is `function noop() -> int { 1 }`; sync and async-sequential loops each do 100 warmup calls then 5,000 timed calls; gather times one 5,000-call batch including Python task scheduling. No LLM/provider/network calls are made.

Interpretation: release-level improvements are clear for these template, join, enum-dispatch, nbody, and concurrent async-completion workloads. The template/join/enum kernels have disjoint tight ranges. Nbody has a noisier upper tail but still a substantially lower median and disjoint ranges. Concurrent async completion has disjoint ranges too. Sequential async is noisier (ranges overlap); omit a quantitative gain from public release notes. Sync no-op is a control with a +9.7% median regression and broad outliers; do not claim all Python calls improve.

Safe public grouping: strings #5432/#5433/#5477 (three PRs), interface/cache #5418/#5431/#5496 (three), allocation/GC overhead #5417/#5429 (two), Python async completion #5497/#5508 (two). These new numbers compare complete fixed releases and do not isolate each grouped PR's contribution; write that explicitly. Nbody gain may include other optimizations and is not solely attributable to #5417/#5429. Avoid a headline blanket speedup percentage.

## Followup array traversal measurement

Same exact release artifacts, hardware, Python interpreter, O2 bytecode, Rust release profile, telemetry-off mapping, and five alternating interleaved process pairs. Source `compute/array-traversal-8k/main.baml`, copied with only main renamed. Each process runs one warmup then times 20 complete kernel calls, dividing by 20. Each kernel builds 8,192 deterministic integers, sums via for-in, sums by index, rebuilds a second array, and sums the rebuilt array; unlike speedtest driver setup mode this includes setup. Python call overhead is included. Lower and upper return the same checksum. Median per job:0.23.0 10.423ms (range9.742–14.167) vs0.24.0 3.573ms (range3.460–3.824), -65.7%. Associate with #5498/#5503 and describe as net fixed-release comparison, not an isolated PR contribution. Raw `/tmp/baml-024-sdk-examples/array-results.json`, runner snippet in tool history, per-process `/tmp/baml-024-sdk-examples/bench_array.py`.
