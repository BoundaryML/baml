## Executive account

Inspected **156 downloaded payloads**, with exact URLs, SHA-256 digests, full archive member inventories, extracted license metadata, and deduplicated license-file contents in [5011-sdk-license-audit.json](5011-sdk-license-audit.json). This includes stable `0.22.2` (canary channel, published 2026-10-13), current nightly `0.22.3-nightly.20261014.a` (published 2026-10-15), Python nightly encoding `0.22.3.dev2026101400`, historical npm bridge `0.20.1`, legacy npm `@boundaryml/baml@0.226.2`, and independently versioned wrapper `0.2.5` (2026-09-11). Registry selection was checked against npm dist-tags, PyPI release upload dates, Maven metadata, NuGet version index, crates.io versions, GitHub releases, and Go/Swift tags. Stable language releases use the npm `latest` tag; there is no separate active npm `canary` dist-tag on the audited bridge packages.

- Independently confirmed: bridge `0.20.1`, current bridge umbrella, all eight native npm companions, and web umbrella omit the top-level `license` field and contain no LICENSE/NOTICE file. Web subpackage manifests inside `dist/wasm` and `dist/workerd-wasm` do say Apache-2.0.
- Independently confirmed: legacy `@boundaryml/baml@0.226.2` advertises MIT in both registry metadata and package.json but bundles Apache-2.0 at `package/LICENSE`. This package is published by the legacy release workflow, not the BAML language workflow audited here; it is included as the issue’s explicit comparison.
- PyPI and crates.io advertise Apache-2.0 correctly, but all inspected wheels and both crates omit the license text. All 16 Python wheels were inspected, not a representative platform. No sdist is published for either audited Python version.
- Java runtime, Kotlin layer, Gradle plugin and plugin marker POMs advertise Apache-2.0. All main, sources, Javadoc, and eight native classifier JARs were checked; first-party LICENSE is absent. Some Javadoc JARs contain Oracle/OpenJDK GPLv2 licensing/Classpath clarification, Assembly Exception, jQuery/jQuery UI MIT terms, and font terms. These are component-specific and do not replace the first-party license.
- NuGet has no license fields in registration catalog entries or nuspec, and no LICENSE. Each nupkg contains all eight expected native RIDs. Swift source mirrors and binary XCFramework zips omit LICENSE; both zips contain three Apple XCFramework libraries spanning five architecture/target builds.
- Go is the positive baseline: both proxy module ZIPs include Apache-2.0 text at the module root. Toolchain archives, standalone VSIX, all wrapper variants, and shared raw CFFI native release assets lack a first-party license file/sidecar. Homebrew formula metadata says Apache-2.0.

`npm view @boundaryml/baml-bridge@0.20.1` using npm 10.9.8 displays `Proprietary`; the exact registry field is **absent**, not a literal `"Proprietary"` value. The npm website could not be fetched by the browser research tool, so its UI was not independently observed. An absent metadata field does not itself change the software’s legal licensing. This audit reports metadata and bundled texts, not a legal re-licensing decision.
