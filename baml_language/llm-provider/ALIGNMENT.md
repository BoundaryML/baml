Each `crates/baml_tests/baml_src/ns_ai_scenarios/NN_*` directory has been rewritten to mirror
its original design in `ideas/scenarios/NN-*` as closely as the real post-desugar surface
allows. To compare a pair, diff the scenario dir against its design dir: the same classes,
functions, and flows appear on both sides; deliberate departures are listed below and marked
inline (`// BLOCKED: P8 ...` for missing host surface). Offline tests need no keys; each
`testset "integ-test-NN-*"` tier runs against real APIs:
`BAML_TEST_TIMEOUT_MS=60000 infisical run --env=test -- baml-cli test --from crates/baml_tests/baml_src -i "integ-test-NN-*::"`.

## 01 — single-turn text

**Aligned:** s01_Summarize is a real LLM function (client + prompt) matching the design's Summarize — same terse-assistant system turn + 'Summarize the plot of {{work}} in one line' user turn; the desugar lowers it to baml.ai.drive_call<string>(client, ...$render_prompt), the same text-in/text-out base call the design exercises; The portability claim: SAME function body, three providers. Offline it is a one-line call-site `client =` override; the live tier drives the identical body through native baml.ai.OpenAi + Anthropic + Gemini (the design's Claude/GPT/Flash), each absorbing its own system-prompt placement inside build_request; Usage as a PRODUCT sidecar: the design's Summarize.call_with(work, m => m.usage()) is s01_Summarize$with(work, projection, client=...) returning CallResult<T,V> (drive_with -> HttpProvider.call_messages_with, a single codec pass). s01_MeteredEcho carries real token numbers so the sidecar is asserted non-zero and is forwarded (not dropped) through combinators; logprobs come back a typed Unavailable, not a silent zero — the design's Supported<T> = T | Unsupported and its 'typed can''t' lesson, matched via `Logprob[] | baml.ai.Unavailable` and a match on the projected value; Refusal is a typed channel, not the answer: s01_Refused implements baml.errors.CallError and is caught most-specific-first (s01_Refused -> CallError -> UnknownError), exactly the design's SummarizeSafe branching. It is raised INSIDE parse BEFORE baml.sap.parse ever runs (the design's load-bearing 'check the refusal channel before parsing' rule), and reports is_policy_refusal()==true while is_network_error/is_rate_limit are false; Combinator chain reads left-to-right off the inherited Provider factories: AlwaysFailProvider{}.with_retry(2).fallback_to(EchoProvider{...}) handed to the same single-turn function via `client =` — the design's Claude().with_retry(2).fallback_to(GPT()); Capability-less client -> typed baml.errors.Unsupported (negotiation), carried over from the prior scenario file; Comments carry the design's key decisions: options-as-plain-fields / no options blob, refusal-before-parse, sidecar-survives-combinators, and the URI header comment linking back to the design dir.

**Divergences:**
- **The design's implement.baml hand-rolled the Anthropic/OpenAI/Gemini providers, the ResponseMeta interface, Usage, Supported<T>, and per-provider wire classes; my implementation.baml does NOT re-declare any of these.** — All of them are now real stdlib (baml.ai.OpenAi/Anthropic/Gemini implement HttpProvider and inherit call/call_with from the codec default; baml.ai.ResponseMeta/Usage/Unavailable exist). implementation.baml holds only the genuinely net-new surface — the refusal channel (s01_Refused) plus two offline fakes (s01_RefusingProvider, s01_MeteredEcho/Meta) needed to exercise refusal + usage deterministically.
- **The design returns a first-class tuple (T, U) from call_with, and projects a combined (Usage, Supported<Logprob[]>) tuple in SummarizeWithUsageAndLogprobs.** — Tuples are not a language feature. The base method returns CallResult<T,V> (a single V), so the combined projection is a scenario-local class s01_MetaSnapshot { usage, logprobs } — the same substitution stdlib itself made (CallResult replaces the design's (T,U)).
- **The design adds a baml.llm.turns / system_text / non_system_turns read-interface over the opaque PromptAst (its single biggest net-new host primitive).** — Not needed on the real surface: the desugar renders the prompt to baml.ai.ChatMessage[] internally and each provider's build_request consumes messages, so no BAML-visible AST-read primitive is required. The three system-prompt placements live inside the stdlib providers, not in scenario code.
- **The design declares three named one-shot clients (Claude/GPT/Flash) and a named Resilient client, then swaps them into one body; plus a second function SummarizeViaGpt to prove the swap.** — The real `client` clause takes a legacy client<llm> as the function DEFAULT; the idiomatic swap is a call-site `client = <provider>` override. I default s01_Summarize to a dead client and show the swap via overrides (offline fakes + the live OpenAi/Anthropic/Gemini tier), dropping the redundant SummarizeViaGpt.
- **s01_Refused implements both baml.errors.Failure (5 methods) and baml.errors.CallError (3 methods); the design's Refused implemented only CallError's 3 classifiers.** — On the real surface CallError requires the Failure super-interface, so a concrete CallError class must satisfy both — which also lets the refusal honestly report is_policy_refusal().
- **Error/closure spellings differ from the corpus: baml.errors.UnknownError (not baml.UnknownError / baml.ExtendUnknownError), and closures are (m: baml.ai.ResponseMeta) -> V { ... } (not m => ...).** — baml.UnknownError does not resolve (E0002) and arrow-closures are not the language's syntax; these were corpus spellings that predate the real surface.

## 02 — structured output

**Aligned:** The headline story is preserved 1:1: ONE return type (S02Event, design's Event) + ONE prompt drives four wire encodings through four functions ExtractEvent_OpenAI/_Responses/_Claude/_Gemini (design names), each mapped in comments to its real provider (OpenAiStrict=response_format #1, OpenAiResponses=text.format #2, Anthropic=schema-append #3, Gemini=responseSchema #4); The T-threaded-twice teaching (build_request<T> lowers reflect.type_of<T>() to schema; parse<T> decodes) is exercised directly and offline via the REAL baml.schema.json_schema(type, strict) — test asserts strict lowering adds additionalProperties:false/all-required and non-strict omits it (the OpenAiStrict response_format toggle); SAP-as-one-parse-branch: offline tests prove SAP recovers S02Event from clean JSON and from prose-wrapped JSON (schema-aligned), through the shared EchoProvider; Portability proof made concrete: the SAME echo reply decodes to the same S02Event through all four entry-point functions in one test; The design's §6 StrictFallback combinator is realized faithfully as S02StrictFallback (implementation.baml): strict primary, loose fallback, forwards HttpProvider via the real call_messages_with seam, declares the same CallError channel, routes the projection to the winning member; a refusal is authoritative and propagates while a non-refusal failure degrades to loose — both behaviors covered by offline tests; Refusal-as-typed-error (design's §1 Refused): realized as S02Refused (concrete CallError with is_policy_refusal()->true) thrown by S02RefusingProvider; TryExtract catches most-specific-first (concrete S02Refused -> baml.errors.CallError -> baml.errors.UnknownError, verbatim design ordering) and returns null on decline vs a real S02Event on success; The fluent chain ExtractResilient uses the real .with_retry(2).fallback_to(...) combinator factories, matching the design's GptStructured().with_retry(2).fallback_to(ClaudeStructured()); Live tier (testset integ-test-02-structured) exercises the four real wire encodings against live OpenAI/Anthropic/Gemini APIs with the same S02Event type and function bodies; All 8 offline tests pass deterministically in the real project (no network/keys); both files compile clean in the shared namespace.

**Divergences:**
- **The four wire encodings are the real stdlib providers (OpenAiStrict/OpenAiResponses/Anthropic/Gemini) rather than re-implemented OpenAIChat/OpenAIResponses/Anthropic/Gemini classes in implementation.baml.** — The stdlib already implements each encoding behind the exact HttpProvider T->build_request<T>->parse<T> seam the design teaches; re-declaring them would duplicate stdlib and is forbidden. Comments map each design class to its real provider.
- **The design's four client-sugar blocks (client GptStructured() { OpenAIChat {...} }) become native-provider overrides at the call site (client = baml.ai.OpenAiStrict {...}) plus a legacy dead default client DeadS02.** — On the real surface an inline native provider cannot be a declared LLM-function client ('Only client and prompt allowed'), and the new `client Name()` sugar does not resolve as a referenceable client name. The proven idiom (matching scenarios 01/29) is a declared default + a `client =` override, which is where the four native providers actually run.
- **Refusal is modeled as a Failure-axis classifier (is_policy_refusal()) carried by the concrete S02Refused, not the design's standalone Refused with is_network/is_rate/is_parse only.** — The real error model (ns_errors/capability.baml) makes CallError require Failure, and the four stdlib providers expose is_policy_refusal on their HTTP-error types; S02Refused implements that axis so it triages uniformly with the rest of the surface.
- **The design's EmptyStructuredError and StructuredHttpError classes are not redefined.** — The real surface already folds these into baml.ai.OpenAiHttpError (status, is_rate_limit->429) and SAP/UnknownError parse failures; adding parallel classes would duplicate existing classified CallErrors.
- **baml.schema.strict_supports(type) and baml.schema.gemini_schema(type) are not used; only the real baml.schema.json_schema(type, strict) is.** — strict_supports and gemini_schema do not exist on the real surface. Strict-mode rejection of a type happens at the provider API (runtime 400), not at lowering time (json_schema even lowers recursive S02OrgNode without throwing), so StrictFallback motivates the retry via a runtime non-refusal failure instead of a pre-call predicate.
- **baml.sap.repair_parse<T> is not used; the real baml.sap.parse<T> is the single decode entry point.** — repair_parse does not exist; the real SAP parser already performs schema-aligned repair (fence stripping, coercion), so the design's separate mandatory repair pass collapses into parse<T>.
- **The design's internal JsonNav and StructuredDecode helpers are omitted.** — They are per-provider response-navigation/decode plumbing that the real stdlib providers implement internally; nothing in the app/library layer of this scenario needs to re-walk raw JSON.
- **S02StrictFallback overrides call_messages_with<T,V,E2> (the real primitive) rather than the design's call<T>/call_with<T,U>.** — The real HttpProvider seam is call_messages_with over ChatMessage[] with a CallResult<T,V> and an E2 projection channel; .call/.call_with derive from it. Overriding it is the faithful realization and lets the projection ride the winning member (the design's P1 fix).

## 03 — constrained decoding

**Aligned:** Constraint vocabulary mirrored 1:1: s03_Choice / s03_Regex / s03_Grammar / s03_JsonShape{schema_of: type} + `type s03_Constraint` = the union (design's Choice/Regex/Grammar/JsonShape/Constraint), with the same doc-comments on each; The capability interface: `interface s03_Constrained requires baml.ai.Provider { decode<T>(prompt: baml.llm.PromptAst, constraint) }` with NO default method — the design's Constrained, including the 'a guarantee can't be faked on an unconstrained .call' asymmetry (the same reason stdlib baml.ai.Constrained ships without a companion); Typed refusal preserved: s03_Unsatisfiable { message, constraint } implements s03_ConstraintError { is_unsatisfiable, is_network_error } — the design's Unsatisfiable + ConstraintError channel; the per-provider deliberate throws all collapse onto this one type; Three self-hosted providers with their divergence isolated inside request_with: s03_VLLM (guided_choice/guided_regex/guided_grammar/guided_json in extra_body), s03_LlamaCpp (GBNF-only: lowers Choice via gbnf_from_choice, refuses bare Regex, gbnf-only Grammar), s03_Outlines (in-process generate.choice/regex/cfg with the lark|ebnf CFG gate); Hosted tier s03_OpenAIHosted implements baml.ai.HttpProvider (strict response_format json_schema) and deliberately does NOT implement s03_Constrained — 'the absence IS the model'; the two-tier split is expressed purely as implements-or-doesn't, verified by the negotiation test; Combinator s03_ConstrainedFallback forwards by runtime delegation, statically claims s03_Constrained, degrades JsonShape to a hosted call and throws Unsatisfiable for Choice/Regex/Grammar (the empty-claim leak); add() + or_else_hosted on s03_ConstrainedCombinators carried over; Client-as-function realized literally: s03_local_llama / s03_llamacpp_box / s03_outlines_box / s03_hosted / s03_portable return baml.ai.Provider (design's LocalLlama/LlamaCppBox/OutlinesBox/Hosted/Portable, 'where it runs' as a plain field); LLM functions s03_Classify / s03_PhoneNumber / s03_ToSql declared with prompt templates (design's Classify/PhoneNumber/ToSql), plus the hand-written negotiation companion s03_classify_decode (design's Classify$decode), s03_guaranteed_label (GuaranteedLabel) and s03_portable_label (PortableLabel) with the most-specific-first catch degrading Unsatisfiable to a hosted schema-JSON call; The stdlib baml.ai.Constrained runtime-promise anchor test (EchoProvider misses -> typed Unsupported) is retained, tying the scenario-local rendering back to the real capability REALIZED.md maps here; 15 offline tests pass deterministically (no network/keys): negotiation, guided_* / GBNF request construction, dialect-mismatch and regex refusals, gbnf_from_choice lowering, Outlines dialect gate, combinator selection + the hosted-only leak.

**Divergences:**
- **Capability signature + channel: stdlib baml.ai.Constrained.decode is thinner (prompt: string, pattern: string; CallError channel)** — It cannot carry the design's closed Constraint union or a typed Unsatisfiable channel, so the rich capability is rendered scenario-local as s03_Constrained (decode(prompt, constraint)); providers implement s03_Constrained (not baml.ai.Constrained) to carry the union and avoid a `decode` method-name collision. One anchor test still exercises the real baml.ai.Constrained.
- **baml.errors.ConstraintError became scenario-local s03_ConstraintError** — The baml.errors namespace is read-only; a net-new capability-error interface cannot be added under it. Kept the exact classifiers (is_unsatisfiable, is_network_error); omitted the stdlib `requires Failure` obligation since it is scenario-local.
- **cast_exact and json_schema_of host primitives** — The real surface has no separate strict-cast primitive, so s03_cast_exact routes through baml.sap.parse (a superset that also accepts an already-exact string); json_schema_of is baml.schema.json_schema(t, false). Design's $rust_io_function boundaries do not exist for scenario code.
- **or_else_hosted lives on s03_ConstrainedCombinators (implemented by concrete providers), not on the Provider marker** — The design put it on Provider so a `client` result could chain it, but the real baml.ai.Provider existential exposes no method surface; it is callable on a concrete self-hosted provider value. s03_portable() builds the ConstrainedFallback directly (like the real Fallback { members }).
- **Expression-style `match` returning a map replaced by statement-style `.set` on a mutable map, building json[] element-wise** — Map-literal-vs-block is ambiguous inside match arms, and string[]/string do not auto-coerce to json in a literal (must be built as json[] / set element-wise) — confirmed by the compiler.
- **render_prompt errors normalized to UnknownError at each decode driver** — Foo$render_prompt throws RenderPrompt | InvalidArgument | LlmClient (the design assumed a pure render_prompt), so each site catch-normalizes to keep the declared s03_ConstraintError | UnknownError channel clean.
- **AllMembersFailed (design's typed CallError combinator-exhaustion) uses plain baml.errors.UnknownError** — Implementing baml.errors.CallError now requires the 8-method Failure+CallError surface; the constrained-path Unsatisfiable (the scenario's real subject) is kept faithfully, so the unconstrained-degrade exhaustion is left as UnknownError to avoid boilerplate.
- **No generated Foo$decode companion; the value+sidecar tuple is CallResult not (T,U)** — Constrained registers no //baml:llm_companion, so the negotiation companion is hand-written exactly as the design showed it 'written out'; the real HttpProvider primitive is call_messages_with over CallResult (tuples are not a language feature).

**Blocked (missing host surface):**
- The guaranteed decode round-trip over a real self-hosted vLLM/llama.cpp endpoint (send+parse): no such backend exists in the harness, so decode() bodies compile and the request-construction + negotiation halves run offline, but the actual guarantee round-trip is live-only. Marked in usage.baml header.
- Outlines in-process generation (s03_Outlines.run_choice/run_regex/run_cfg/run_json): no in-process transformers/Outlines runtime — the dispatch and lark|ebnf dialect gate compile and are tested; the generators throw a `// BLOCKED: P8` marker (asserted by a test).
- llama.cpp json-schema -> GBNF lowering (design's gbnf_from_json_schema $rust_io_function): nontrivial host primitive unavailable, so JsonShape on s03_LlamaCpp throws Unsatisfiable with a `BLOCKED: P8` note.
- Outlines' HTTP-less request/response face (implementing baml.ai.HttpProvider via an in-process call_messages_with override — the evaluation's 'request/response is the capability, not speaks-HTTP' point): needs the in-process host, so s03_Outlines implements only Provider + s03_Constrained; noted BLOCKED.

## 04 — streaming

**Aligned:** Streaming capability + the auto-generated $stream companion IS the design's `.stream`: token streaming (TStream=string) and streaming partial structured output (TStream=s04_Meeting$stream) both come off the SAME function (s04_Haiku / s04_ExtractMeeting) — the design's central 'same stream, richer read' thesis; s04_Meeting = the design's Meeting schema (title/date/attendees); pull-based consumer loop mirrors the design's while/match: `match s.next()` over partial | StreamFinished, then `s.final()` for the validated answer (design's next()/final()/StreamDone shape); partial structured output is proven to be a client-side interpretation selected by the function's return type, not a distinct API mode (design §B); resilient chain `AlwaysFailProvider{}.with_retry(2).fallback_to(...)` is a Provider handed to the SAME $stream companion (design's ResilientStream = GPT4o().with_retry(2).fallback_to(GeminiFlash()) portability seam); non-streaming provider off $stream negotiates to a typed baml.errors.Unsupported (design's EchoModel/Canned degrade case, on the real drive_stream path); s04_negotiate reproduces the design's fallback-to-call seam as a capability probe: a provider can be HttpProvider (has .call) yet NOT Streaming; live testset integ-test-04-streaming runs ONE consumer loop across OpenAi (flat SSE deltas), Anthropic (SSE event grammar), and Gemini (chunked JSON) — the design's three-divergent-transport portability proof, plus a fallback chain that streams.

**Divergences:**
- **No implementation.baml (the design's 628-line library-author file)** — The design's three custom providers (OpenAI/Anthropic/Gemini) and their hand-rolled stateful folds (fold_sse/fold_events/fold_chunks, StreamAcc) are fully SUBSUMED by the real stdlib: OpenAi/Anthropic/Gemini already `implements Streaming` natively (stream_messages in Rust). Nothing custom is left to author, and the directive says prefer real LLM functions / don't re-implement existing providers.
- **MeetingPartial is not hand-written; TStream/TFinal are never spelled by the app** — The real $stream companion takes 0 type args and auto-derives the partial: `Foo$stream(...)` returns `Stream<T$stream | null, T>`. So the design's hand-declared MeetingPartial is just `s04_Meeting$stream`, and the two-type-param call form `stream<TStream,TFinal>` from the design's usage.baml is not how the surface works.
- **StreamDone -> baml.stream.StreamFinished, plus a null arm** — The real sentinel is baml.stream.StreamFinished (not StreamDone), and next() yields `partial | null | StreamFinished` — the null (no-text frame) arm is a third match case the design's loop didn't have.
- **Consumers return assertable values; resilient offline test asserts 'no-stream'** — Offline the fake members don't implement Streaming, so a Fallback chain throws UnknownError ('fallback: no streaming member') rather than Unsupported — an honest outcome distinct from the single-provider Unsupported degrade; wrappers return strings/Meeting so offline tests can assert deterministically.

**Blocked (missing host surface):**
- buffer_as_stream honest degrade (design §D): a non-streaming provider answering .stream by buffering .call needs baml.llm.stream_unfold + stream_once + baml.sap.partial_of — none exist; drive_stream throws a typed Unsupported instead (confirmed by the baml.ai.drive_stream docstring). Marked `// BLOCKED: P8` in usage.baml.
- Mid-stream cancellation (design §E s.close()): baml.llm.Stream exposes only .next()/.final(), no .close(). Marked `// BLOCKED: P8` at the token consumer loop.
- The entire net-new host surface the design's implement.baml §0-§7 introduced is absent: baml.llm.stream_unfold / stream_once, baml.sap.parse_partial (public) / partial_of, baml.http.fetch_json_seq + JsonSeq, baml.llm.{openai,anthropic,gemini}_mark_stream, and the StreamStep helper. These are why no library-author file could be written.
- Byte-level incremental streaming (partials actually filling in) is not offline-deterministic (needs network/keys) — it lives entirely in testset integ-test-04-streaming; the offline tier can only prove companion negotiation + that the same consumer typechecks for both deliveries.
