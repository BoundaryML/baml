# Scenario 07 — Reasoning models (effort, verbosity, thinking, continuity)

This scenario stresses the Provider/capability model against reasoning models, where the hard parts are: reasoning is a *distinct content kind* (not text, so it must be displayed/billed/stripped without contaminating the answer `T`); two incompatible control models (OpenAI's categorical `effort` vs Anthropic/Gemini's token *budget*) plus a separate `verbosity` knob; and lossless cross-turn *continuity* of signed/encrypted thinking — including OpenAI's server-held state. The two halves of reasoning split across the **value+sidecar partition**: the reasoning *text* (the displayable/billable view) *accompanies* the answer, so it is a **product sidecar** carried by `call_with` + a `ResponseMeta` projection (`ReasoningMeta.reasoning_blocks()`, an external-impl dimension reached by `match`) — the bespoke `Thinks.think -> WithReasoning<T>` companion and the `WithReasoning<T>` carrier are **gone**. Extracting the continuation *handle* is likewise a sidecar (`ContinuationMeta.continuation()`), but *threading it back* is a stateful round-trip, so it stays on the `Continuity` capability whose `resume<T> -> T` (plus a `resume_with` value+sidecar form) replaces the wrapper return. Under the per-capability error model, `Continuity.resume` is a distinct stateful protocol, so it keeps its **net-new `baml.errors.ContinuityError` channel** with an `is_cross_provider()` classifier and a concrete `CrossProviderContinuity` error. `usage.baml` shows the ergonomics (tuple destructuring of `(T, Supported<…>)`, uniform projection across reasoning and plain providers), where portability leaks, and a multi-turn function whose error channel is the *union* `CallError | ContinuityError`; `evaluation.md` is adversarial about the server-state, the two-channel union, and Fallback-vs-continuity failure modes, and records P1 as resolved-with-mechanism for the reasoning-text sidecar.
