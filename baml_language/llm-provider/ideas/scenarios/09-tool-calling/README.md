# 09 — Function / tool calling basics

This scenario stresses the `Tools` capability seam: the model picks a function and arguments, your code runs it, and the model continues with the result. The app author declares tools once (a `Tool` whose `parameters` is a first-class `type`), writes a function, and calls the `.run_tools` companion — while the provider absorbs every divergence below the seam: one schema rendered to three dialects (JSON Schema for OpenAI/Anthropic vs the Gemini OpenAPI-3 subset), id-vs-name correlation (OpenAI/Anthropic stamp ids, Gemini has none and we synthesize them), and three result-threading shapes (`role:"tool"` message vs `tool_result` block in a user turn vs `functionResponse` part, including Anthropic's positional ordering). `implement.baml` is the library/provider code (OpenAI, Anthropic, Gemini, and a `ToolFallback` combinator); `usage.baml` is the application code; `evaluation.md` is the adversarial read (engaging Open Questions #1 and #5). Non-model state is injected via `ExecutionContext.deps`.
