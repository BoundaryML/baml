# Scenario 28 — Provider diversity & gateways

How the proposed model handles "call many models — possibly through a proxy or gateway — without rewriting per provider, and switch backends by changing a string." The whole story here is *clients are functions that return a Provider*: `base_url` and `headers` are ordinary provider fields, so an OpenAI-compatible proxy (Groq, Together, Ollama, an internal gateway) is just the `OpenAIChat` class with a different `base_url`; auth-shape divergence (Bearer / `x-api-key` / `?key=` / cloud IAM SigV4 / OAuth) is a typed `Auth` field the codec applies; and prefix routing / a provider registry (LiteLLM, Vercel `createProviderRegistry`) collapses into an ordinary function — `Registry.resolve(spec)` — that `match`es a string prefix and constructs a provider. `implement.baml` is the library code (providers, `Auth` variants, the registry, the `Normalized` LCD-bridge and its escape hatch); `usage.baml` is the app surface (one function body across six backends); `evaluation.md` stresses where it leaks — the registry's runtime-only capability promise, per-request override knobs, and auth-ordering vs the combinator-header rule.
