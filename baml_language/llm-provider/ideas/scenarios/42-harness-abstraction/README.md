# 42 — Wrapping harnesses behind one abstraction

The newest move in the space: the same abstraction step applied to *providers* (one interface over many APIs) applied to *harnesses* — one agent interface (`HarnessAgent`) over many runtimes (Claude Code / Codex / Pi), whose output flows into the same streaming/UI surfaces you already use for a plain model call. In this proposal that abstraction is nearly free, because a harness *is* a `Provider`: `HarnessAgent` is a combinator that wraps a runtime and forwards by delegation, and its `.stream` returns the same `baml.llm.Stream` a chat model emits. Where it strains is everything *stateful*: session lifecycle across server boundaries (`create_session`/`detach`/`attach`/`destroy`, a net-new `Harness` capability with a durable, opaque `SessionHandle` and a server-authoritative `SessionExpired`), and lossy normalization — `rewindFiles` (Claude) and `steer` (Pi) have no common method, so they ride an explicit `raw()` escape hatch and are negotiated at runtime, never typed. `implement.baml` is the library layer (`Harness`/`AgentStreaming` capabilities, the `HarnessAgent` facade, two divergent runtime adapters, the `ServerSession` cross-request driver); `usage.baml` is the app layer (runtime swap in one line, the two-handler server dance, the rewind escape hatch); `evaluation.md` is the adversarial read.
