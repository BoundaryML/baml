# 21 — Memory (cross-conversation, long-term)

Cross-conversation memory is the agent remembering facts about a user across all their chats (vegetarian; dog named Bella) and recalling the relevant ones later. The load-bearing insight for this proposal: **memory is not a `Provider`** — a provider produces a typed answer, a memory layer stores and recalls facts — so this scenario introduces a sibling `MemoryStore` interface (with a `VectorStore` "disk" underneath) and shows the proposal's machinery wiring memory into a call three ways: as **middleware** (a combinator that wraps a `Provider` for retrieve-before / store-after, the mem0 implicit extract→decide→persist pipeline running as ordinary `.call`s), as a **tool the model drives** (mem0's `search_memory`, Anthropic's memory-tool filesystem, Letta's self-editing `core_memory_*` — all the canonical `Tools` loop with new handlers), and the limit case where state is **server-authoritative** (Letta) and can only be proxied as an opaque `Provider`. `implement.baml` is the library code; `usage.baml` is the app code; `evaluation.md` stresses where the opaque `PromptAst`, caching, and server-side state leak.
