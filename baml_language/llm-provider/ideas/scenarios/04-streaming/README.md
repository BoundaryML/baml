# Scenario 04 — Streaming tokens + streaming partial structured output

This scenario stresses the `Streaming` capability. One interface (`stream<TStream, TFinal> -> baml.llm.Stream<TStream, TFinal>`) has to span three divergent wire formats — OpenAI's flat SSE deltas, Anthropic's structured SSE event grammar, and Gemini's chunked-JSON array (which an SSE parser cannot read) — while a non-streaming provider still answers `.stream` by buffering its `.call`. The payoff to look for: **streaming partial structured output is not a separate API mode**, it's the *same* token stream re-read by a client-side tolerant parser, so the app picks `TStream = string` for a typewriter or `TStream = MeetingPartial` for a live-filling object off the identical function. `implement.baml` holds the provider folds, the stateful `StreamAcc`, and the `stream_unfold` / `fetch_json_seq` / `parse_partial` net-new primitives; `usage.baml` shows the app author writing config-only clients and consuming the stream; `evaluation.md` argues this is *Workable-with-additions* and flags where the `Body` seam (Open Question 4) fails to carry streaming and where fallback + a compile-time incremental guarantee can't coexist.
