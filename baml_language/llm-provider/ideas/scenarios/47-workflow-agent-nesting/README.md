# 47 · Agents inside workflows, workflows inside agents

Nesting goes both ways. A deterministic, replayable workflow can have one step whose body is a full agent run — a `Provider` with `Tools` driving a multi-turn loop — and we fence that whole loop behind a single checkpointed activity so a replay returns the recorded answer instead of re-sampling the model. Conversely, because the proposal makes a `client` sugar for "a function returning a `Provider`" (now a bare composable *marker*, with `call`/`call_with` owned by the `HttpProvider` capability — see `../provider-as-marker.md`), a whole durable workflow IS a `Provider`: having a request/response shape it `implements HttpProvider`, so we adapt it to be handed to an agent as one `Tool`, with its tokens and cost rolling up to the calling turn. `implement.baml` adds the durable-engine seam, the `Durable` combinator, the `Workflow` interface, and the `WorkflowProvider` adapter; `usage.baml` shows both directions with two divergent providers (Anthropic and OpenAI agents) that the nesting code never branches on. The hard parts — two nondeterminism models meeting at the boundary, trace/cost roll-up, and the agent step as a single checkpointed activity — are where the model is stressed in `evaluation.md`.
