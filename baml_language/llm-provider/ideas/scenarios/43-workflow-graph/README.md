# 43 — Composing a durable step graph

A step graph (Mastra's `.then/.parallel/.branch/.dountil` chain, pydantic-graph's node DAG, LangGraph's `StateGraph`) is, in the proposed model, just ordinary BAML: a step is a typed `function`, an edge is a `let`, a branch is a `match`, a loop is a `while`, and a model call inside a step is a plain `provider.call<T>(...)`. So the provider/client/capability model is almost a spectator here — it cleanly carries the *node* (including a model-decides agentic node, reused as the `Tools` capability) and keeps the two divergent providers (OpenAI `response_format` vs Anthropic forced-tool) portable behind identical call-sites. What the host language does *not* give for free is the two things that make a step graph a *graph* and *durable*: a concurrent fan-in/join sync barrier (`baml.async.join2/join_all` — the net-new structured- concurrency seam) and checkpointed resume (`Checkpoint` + a `step(...)` memoizer). Both sit deliberately outside the Provider hierarchy. `implement.baml` is the library/host layer; `usage.baml` is the doc-pipeline graph an app author writes; `evaluation.md` stresses where this leaks — chiefly: no portable graph IR, no compile-time guarantee an agentic node is tool-capable, and only shallow (output-level, not mid-step) durability.
