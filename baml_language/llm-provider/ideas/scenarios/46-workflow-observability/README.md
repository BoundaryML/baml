# 46 — Streaming & observability of a workflow

A workflow is an orchestrator that calls models — the layer *above* a single call. This scenario models a workflow as an ordinary `Provider` (its `.call` runs the graph to its result) that adds a net-new `Steppable` capability whose companion, `.steps`, yields a `baml.llm.Stream<StepEvent, T>`: a per-step event hierarchy (step-start / step-token / step-result / step-suspended / workflow-finish) keyed by step id, reusing the *same* Stream type streaming uses. Inside a step that calls a streaming model, the inner token stream is multiplexed up as `step-token` frames, and each step opens an obs span under which the §32 `Traced` combinator nests every model span — so the graph renders as a span tree. The durable step log (`baml.flow`) gives per-step replay / time-travel. Read `evaluation.md` for where this leaks: the inter-step carry is `unknown` (the graph is untyped), the token multiplex is buffered rather than truly interleaved, replay fidelity is unenforced, and durable suspend/resume is approximated through out-of-band host state rather than a language primitive.
