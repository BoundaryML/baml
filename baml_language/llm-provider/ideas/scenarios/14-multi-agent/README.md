# 14 — Multi-agent

Several specialized agents cooperate instead of one giant prompt: a router hands off to specialists, a parent calls sub-agents as tools, or code sequences agents deterministically. This scenario shows all three on the model-decides ↔ code-decides spectrum, expressed on the proposal's spine: an agent *is* a `Provider`, a handoff is a `Tools` combinator that synthesizes `transfer_to_*` and swaps the active provider, a sub-agent-as-tool is a `Provider` adapted into a `Tool`, and deterministic orchestration is plain combinators that only implement `Provider.call`. It also makes the two incompatible state-threading models (history vs shared state) an explicit `Threading` type the author must pick, and adds the depth cap the SDKs leave uncapped. `implement.baml` is the library surface; `usage.baml` is the app surface (Anthropic + Gemini leaves to prove the wire divergence stays inside the providers); `evaluation.md` is the adversarial read.
