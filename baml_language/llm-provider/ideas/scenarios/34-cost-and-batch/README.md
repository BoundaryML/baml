# 34 — Cost & tokens + batch / async inference

This scenario stresses the proposal on metering and money. Usage is a **product sidecar** (value AND metadata), so it rides the `call_with<T,U>(prompt, project) -> (T, U)` seam owned by the `HttpProvider` capability (the marker `Provider` carries no interaction method — `call`/`call_with` belong to `HttpProvider`, see `../provider-as-marker.md`) plus the `ResponseMeta` interface — the app matches the client's provider for `HttpProvider` and writes `h.call_with(text, m => m.usage())`, destructuring `(Ticket, Usage)`. There is no bespoke `Metered<T>` / `call_metered` capability anymore: each provider maps its own wire dialect (OpenAI `prompt/completion`, Anthropic `input/output` + cache itemization, reasoning hidden-but-billed) into one canonical `Usage` *inside* its `ResponseMeta` impl (`OpenAIResponse.usage()` / `AnthropicResponse.usage()`), and two pricing-specific dimensions (which model served, which tier) ride a small external `MeteredMeta` interface. Because `call_with` lives on the same capability as `call`, Fallback/Retry/Cache forward it — the winning member's usage is never silently dropped. A `Budget` combinator wraps a `Provider` and sums usage across a fan-out tree against a price matrix whose `PricingMode` makes batch/flex/priority a multiplier — this is a SUM/stateful round-trip, **not** a `call_with` sidecar, so it stays a hand-threaded combinator (the running total needs mutable host state the `client` sugar can't hold) that `implements HttpProvider` (it forwards request/response) and *projects* the inner member's `call_with` to charge. Batch (submit → poll → download, ~50% off, separate rate pool, unordered results rejoined by `custom_id`) is also a SUM outcome (the handle replaces the answer), so it keeps its own server-authoritative lifecycle capability, reusing the background-jobs handle pattern. `implement.baml` is the library code, `usage.baml` the app code (OpenAI + Anthropic, to show portability and its leaks), and `evaluation.md` is the adversarial read.

Resolves **P1** for the metering pile with a named mechanism (`call_with` + `ResponseMeta`, see `../../value-sidecar-model.md`); leaves budgeting (sum/stateful) and batch (handle-replaces-answer) on their own mechanisms, which were never P1's problem.
