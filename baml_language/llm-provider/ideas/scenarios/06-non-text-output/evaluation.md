# Evaluation — Non-text output (image / speech / transcription)

Adversarial read of the proposal against output-specialized providers, the dedicated-vs-in-conversation split, and mixed-modality responses.

> **Update (value+sidecar model).** The two cost meters and the provider-revised prompt — both **product sidecars** ("the value, *plus* metadata about it") — no longer ride a bespoke `Metered`/`last_usage` companion (with its own `baml.errors.MeterError` channel) or a `Media.revised_prompt` / `MixedReply.usage` value field. They are projected out of the normalized **`ResponseMeta`** via the base **`call_with<T,U> -> (T, U)`** ([`../../value-sidecar-model.md`](../../value-sidecar-model.md), `_conventions.md` "Value + sidecar model"). This is what closes the old (c)#3 "two cost meters have no home" awkwardness and the (c)#4 "revised_prompt has no slot" note below — they are folded into the resolution and the original text is kept (struck-through in spirit) for the audit trail.

## (a) What the proposal reuses unchanged

- **`HttpProvider` with associated `type Body`.** Every provider here is an `HttpProvider` (`Body = baml.http.Response`); the proposal's claim in §2 — "the difference is the body, not the interface" — holds. `GptImage` and `GptTts` decode the *same* `Response` body differently (`baml.json.parse(from.text())` + navigating to `data.0.b64_json` via the `map`/`json[]` arms vs `from.bytes()`), and that is the entire divergence. No new request/response codec — and the JSON read uses the REAL `baml.json.parse` over the `json` union, not an invented `Response.json_path`.
- **The default `call` from `HttpProvider`.** None of the four providers writes `call` — they inherit `parse(send(build_request))`. The output being an image changes nothing about the call wiring.
- **`Streaming` as a delivery refinement.** Partial-preview images and partial STT text both slot into the existing `Streaming` interface; `.stream` degrades to `.call` for any provider that lacks it, exactly per §5.
- **Combinators via default methods, including the error channel.** `.with_retry(2)` and the custom `SaveTo` wrap a Media-producing provider with zero special-casing — `SaveTo` is a plain non-generic class that `requires Provider` (the marker, for the inherited `with_retry`/`fallback_to`/`cached` factories) and `implements HttpProvider`, because the interaction it forwards is request/response and `call`/`call_with` live on `HttpProvider` now (`Provider` is a bare marker — [`../../provider-as-marker.md`](../../provider-as-marker.md)). Its primitive is `call_with`, which `match`es the inner provider for `HttpProvider` and **forwards `project` to the inner `call_with`** — so the usage/revised-prompt sidecar survives the combinator (the actual P1 win: a `SaveTo`-wrapped provider does *not* drop the meter the way an old `.call`-only forwarder would). It declares the *same* `baml.ExtendUnknownError<baml.errors.CallError>` channel as the provider it wraps; the inner provider's `Refused`/`OpenAiMediaHttpError`/`UnknownError` forward straight through with no narrow/widen/forward gymnastics (error-model rule 4). Note the best-effort `persist_if_media` catch is a *local swallow* (non-media `T` is a no-op), not a rethrow — the only place a `catch (e) { _ => ... }` legitimately discards.
- **The compile-time escape hatch.** `DallePrecise() -> GptImage` (dropping the `client` sugar) is the only way to make "yields only images" static — used verbatim as §3/§5 prescribe.
- **`T` threaded through `parse`.** `parse<T>` is already generic, so pinning `T = Media` or `T = MixedReply` needs no new machinery (§2, Open Q4).

## (b) Net-new surface it must add (each tied to a primitive)

- **`class Media { mime, data?, url? }`** — a value type. The proposal has no media result type; "output is not a string" forces one. Ties to the `T` generic: it is just another `T`, but a *standard library* one the ecosystem must agree on so providers interoperate. (`revised_prompt` is *not* a field here — it left the value to become the `RevisesPrompt` sidecar; see below.)
- **`class Usage` + a `ResponseMeta`-projected sidecar** — net-new *value type*, NOT a net-new capability. Two cost meters (`mainline_tokens` + `generation_units`) cannot be a field on the base `Provider`, and folding them into the answer `T` only works on the in-conversation path — so they ride `call_with` + `ResponseMeta.usage()` instead. **This removes the previously net-new `Metered` interface AND the `baml.errors.MeterError` channel entirely** (see the struck (c) notes): reading usage is no longer a separate fallible method, it is a pure projection over a body the codec already parsed, so it rides the `CallError` channel of the `call_with` that produced it. The only genuinely net-new surface left is the `Usage` *shape* (a std-lib value type the ecosystem must agree on) and the **tuple `(T, U)`** return (see (b·tuples) below).
- **TUPLES `(T, U)` are required net-new language surface.** `call_with` returns `(T, U)` and the app destructures `let (reply, u): (MixedReply, Usage) = …call_with(…)`. First-class tuple types + tuple destructuring are not in the spine today; this scenario depends on them exactly as the value+sidecar model flags (they are shared with the streaming folds, not bespoke to metadata). A named `Output<T,U> { value, extra }` struct is the fallback if tuples are rejected, at an ergonomic cost.
- **`RevisesPrompt` — an external-impl `ResponseMeta` dimension.** `revised_prompt` left the `Media` value and became a sidecar. Because only the image endpoints rewrite prompts, it is modeled as a small *external* interface (`interface RevisesPrompt { revised_prompt(self) -> Supported<string> }`) that `OpenAiImageResponse`/`OpenAiResponsesResponse` implement and the app reaches by a runtime `match (m) { let rp: RevisesPrompt => … }` — the §7 "novel dimension added later" pattern. `Supported<string>` keeps "this provider can't revise" distinct from "no rewrite this call". This is reused machinery, not new surface, beyond the one-line `Supported<T>` std type.
- **A typed `Refused` + `OpenAiMediaHttpError { status }`.** The old model funneled every deliberate decline (image moderation, tts/stt/responses non-2xx) into one untyped `throw baml.errors.LlmClient { message }`. The new model promotes them to concrete classes that `implement baml.errors.CallError` (and `StreamError`, since moderation/HTTP failures can also land mid-preview-stream). `Refused` is the canonical refusal shape; `OpenAiMediaHttpError` carries the status. This is a real gain: image-gen prompt moderation was always a *distinct* domain outcome, and it is now a first-class typed branch (`DrawOrExplain` catches it by name) instead of a string the app must regex.
- **`baml.media.*` host primitives** — `image_from_base64`, `audio_from_bytes`, `from_url`, `as<T>`, `persist_if_media<T>`. These are `$rust_io_function`-class host boundaries (Open Q6/Q7 territory): base64/byte decode cannot be written in pure BAML. `baml.media.as<T>` in particular is a **downcast at the host boundary** — `parse<T>` must return `T`, but the provider only ever produces `Media`; something has to assert `Media : T`. That assertion is net-new and unsafe (see (c)).
- **`baml.llm.prompt_text` / `multipart_audio` / `stream_from_sse` / `stream_text`** — PromptAst accessors. `prompt_text` (flatten the AST to raw text for a dedicated endpoint that has no role structure) and `multipart_audio` (pull a media *input* part out of the AST for STT) are new readers on the opaque `PromptAst`. The proposal treats `PromptAst` as fully opaque; non-text I/O needs to crack it open.
- **`class MixedReply`** — the in-conversation path's `T`. Net-new, and it is the leak point below.

## (c) Where it is awkward, leaky, or unresolved

- **The dedicated/in-conversation split is NOT portable — `T` diverges.** This is the headline failure. `GptImage.call` returns `Media`; `Gpt55.call` returns `MixedReply`. There is no single `T` that both produce, so `TwoPaths` in usage.baml must reach into `mixed.media[0]` by hand. The proposal's portability story ("swap the client, keep the function") breaks precisely where the background says it must — the two paths "differ in result extraction" and "an abstraction has to paper over both." The model does not paper over it; it surfaces the seam as a different return type. An app cannot write one function `-> Media` and point it at either provider.
- **`parse<T>` returning `T` for an output-specialized provider is a lie the compiler can't catch.** `GptImage.parse<T>` is generic in `T` but only ever produces `Media`. If an app writes `function Draw() -> Resume { client: Painter() }` the type checker is happy (the `client` returns the existential `Provider`, whose `call<T>` is generic), and it blows up at runtime inside `baml.media.as<T>`. This is **Open Question 4** sharpened: the seam is `Body`, yes, but an output-specialized provider also wants to *constrain its output type*, and the existential-`Provider` return throws that constraint away. The only fix is the §3 escape hatch (`-> GptImage`), i.e. *abandon the client sugar* — so the sugar and the safety are mutually exclusive here.
- **~~Two cost meters have no home on `call`.~~ RESOLVED by `call_with` + `ResponseMeta`.** *(Original concern: `call<T>` returns only `T`; we modeled usage as `Metered.last_usage(self)`, which was stateful-on-the-provider-value, raced under concurrency, and was silently dropped through a Fallback that forwarded `.call`. Folding it into `T` only worked on the in-conversation path.)* The value+sidecar model gives usage a first-class, **uniform** home: `m => m.usage()` projected through `call_with` on **both** paths (`CostAwareDraw` for `-> Media`, `CostAwareIllustrate` for `-> MixedReply`), normalized lazily by each provider's `ResponseMeta` impl. No stateful provider value, no concurrency race, no silent drop — combinators forward `call_with` structurally (the actual P1 win). The dedicated impls hard-code `mainline=0`; `OpenAiResponsesResponse.usage()` reads the real two-meter figure off the body.
- **~~`revised_prompt` has no slot.~~ RESOLVED — it is a sidecar now.** It left the `Media` value type and became `RevisesPrompt.revised_prompt(self) -> Supported<string>`, projected via `call_with` (`DrawAndShowRewrite`). This is the literal "the value, *plus* what the provider changed about your request" case the value+sidecar model is for. (Moderation declines still — correctly — ride the `throws` channel as a typed `Refused`; that is a *sum* outcome, not a product sidecar, and was never P1's problem.)

- **~~NET-NEW: usage-reading needs its own error channel.~~ DELETED by the value+sidecar model.** *(Original concern: `Metered.last_usage` was none of call/stream/tool/realtime, so it dragged in a fifth `interface baml.errors.MeterError` whose `is_rate_limit` classifier was meaningless for a local read — the "one interface per capability with common classifiers" rule fraying.)* With usage as a `ResponseMeta` projection there is **no separate fallible method**, so there is **no `MeterError`**. The projection runs inside `call_with`, whose failures are already `CallError`. This is a strict win: the thin "read a number" capability that didn't fit the classifier vocabulary no longer needs a channel at all.

- **The `Refused`/`OpenAiMediaHttpError` `implements StreamError` is forced, not free.** Because partial-image preview streaming exists on *both* `GptImage` and `Gpt55`, a moderation decline or a non-2xx can surface mid-stream as easily as on `.call`. So each concrete error must `implement` both `CallError` and `StreamError` — and the two `implements` blocks are byte-identical boilerplate (all classifiers return the same bools). The model gives no way to say "this error is the same on every channel"; you re-state the classifier methods per interface. For a scenario with four providers each raising the same two error classes on two channels, that is a lot of duplicated `return false;`.

- **Concrete error through the existential `Provider` survives but stops being statically discoverable.** `Painter()` returns the existential `Provider`, so `DrawFox`'s static error type is `baml.errors.CallError | baml.UnknownError` — the `Refused` concreteness is no longer *advertised* by the channel, the same way the output type narrows to the existential's `Media` (the same existential-erasure leak as (c)#2, now on the *error* side). But the error itself is not destroyed: a `Refused` that crosses a boundary and gets normalized through rule 3's trailing `with_message<CallError>` is boxed into `baml.UnknownError` with the original value untouched in `.data`, and re-asserting `from<Refused>(e)` (or `from<CallError>(e)`) at any later layer where that type is back in scope pulls the *same* concrete error back out, classifiers intact. Recovery is **explicit, never transparent**: a plain `let r: Refused =>` arm tests the runtime type of `e` *itself*, and a boxed error *is* a `baml.UnknownError` (which does not implement `Refused`/`CallError`), so that arm never fires on it — the app must reach into the `UnknownError` arm and call `baml.UnknownError.from<Refused>(e)` by hand. What is missing is the *static* signal that this is recoverable: the channel does not enumerate which concrete refusals can reach you, so recovery is by speculative `from<…>` probe, never type-directed (this is the P2-analog — capability-as-runtime-promise applied to the error side). The cost is firm, not conditional — a plain catch across this boundary only ever sees `CallError` or `UnknownError`, and nothing in that type tells the author the down-stack `Refused` is sitting in the box worth probing for. The one place this scenario's typed-refusal win is *statically visible* — advertised on the channel, not merely recoverable — is again the §3 escape hatch (`-> GptImage`). The sugar de-types the error the same way it de-types the output: in both cases the value survives and the static signal is what's lost.
- **Honest residuals the value+sidecar model carries (not introduced here — they are the model's *existing* tensions).**
  - **Fallback aggregate = the winner's view only.** `project` runs over **one** `ResponseMeta`. If `SavedPainter` (or a `Painter().fallback_to(...)`) burns a moderation-failed first member, the `generation_units` you paid for on that member have nowhere to go — the product shape carries the winner's `Usage`, not the chain's. Same aggregate-provenance gap as the error side.
  - **Per-field absence is a runtime promise (P2, localized).** `Supported<string>` makes "this provider can't revise the prompt" / "no logprobs on an image endpoint" *typed and self-explaining*, but **which** dimensions a given client supports is still answered at runtime (an `Unsupported` value or a `match` miss on `RevisesPrompt`), never by the static type of the existential `Provider` the `client` returns.
  - **The external-dimension escape hatch rides OQ5 wrapper-transparency.** `m => match (m) { let rp: RevisesPrompt => … }` (and any `let o: OpenAiImageResponse => baml.json.parse(o.raw.text())…` reach) silently misses if `m` is a framework wrapper (`FrameworkMeta`/`CacheMeta`) over the provider response rather than the response itself — the *same* occlusion as `UnknownError` boxing a concrete error and `Fallback` hiding its member. Cure is the same: probe through the layers (OQ5). Metadata does not escape it.
  - **Sums and stateful round-trips stay on their own mechanisms — and should.** `call_with` deliberately does **not** absorb the `Refused` moderation decline (a *sum*: no usable `T`; it stays on the `throws` channel as a typed `Refused`/`OpenAiMediaHttpError`), nor any suspend/background/handle case. `(T, U)` promises a `T`; those have none. The partition is intact here.
- **Open Question 6 (SAP as a public primitive)** is load-bearing here in an inverted way: `GptStt` is the one provider whose output *is* text and *does* want `baml.sap.parse<T>`, sitting right next to `GptImage`/`GptTts` which must NOT use SAP. The proposal's "SAP is one branch of parse" framing handles this, but only because every provider hand-picks its decode — there is no shared default, so each non-text provider re-implements `parse` from scratch.

## (d) Verdict: **Workable-with-additions**

The base model genuinely absorbs non-text output where the background says it should: the `Body`-associated codec lets `GptImage` decode bytes and `GptTts` decode audio over the identical `HttpProvider` interface, `Streaming` covers partial previews, and combinators compose over media values unchanged. That is a real win and it costs only value types (`Media`) plus host decoders.

**P1 (the value+sidecar problem) is resolved-with-a-named-mechanism for the product sidecars in this scenario.** The two cost meters and the provider-revised prompt — the entire metadata pile here — now ride `call_with` + `ResponseMeta` ([`../../value-sidecar-model.md`](../../value-sidecar-model.md)): usage is one uniform `m => m.usage()` projection on **both** the `-> Media` and `-> MixedReply` paths, normalized lazily per provider and forwarded by combinators instead of dropped through a Fallback; `revised_prompt` is an external `RevisesPrompt` dimension reached by `match`. This **deletes** the previously net-new `Metered` capability and the `baml.errors.MeterError` channel outright. The cost is the required net-new **tuple `(T, U)`** surface (shared with the streaming folds) and a std-lib `Usage`/`Media`/`Supported<T>` contract. The honest residuals are the model's own, not new: the Fallback aggregate carries only the winner's `Usage`; per-field support (`Supported`/`match`-miss) is a runtime promise (P2); and the external-dimension `match` rides OQ5 wrapper-transparency.

What the value+sidecar model does **not** touch is the headline divergence: the proposal still does not paper over dedicated-vs-in-conversation — it exposes it as two different answer `T`s (`Media` vs `MixedReply`), which is honest but defeats client-swap portability for exactly this scenario, and output-specialized providers still want a compile-time output *constraint* the existential-`Provider` sugar can't give (drop to `-> GptImage`). Those are *value-`T`* problems, orthogonal to the sidecar carrier. Workable, now with a clean home for the metadata: with a standard-library `Media`/`Usage` contract and tuples, the only remaining leak is that "swap the client" stops being safe the moment the **answer** type itself diverges.
