# 12 · Tool taxonomy — hosted / computer-use / MCP (execution location)

"A tool" is five different things that differ by **who executes the call and where**: a client-executed function (your code), a provider-hosted tool you can only declare-and-observe (`web_search`, `code_execution`), a computer-use hybrid (the model proposes clicks, your code performs them and returns screenshots), a remote MCP server the provider dispatches to, and human-in-the-loop approvals layered on any of those. This scenario shows the proposal's `Tools` capability handling the function case unchanged, then introduces the net-new surface the other four force: a `ToolKind` union that makes *execution location* a first-class variant (not just name + schema), a `MixedTools requires Tools` capability whose `step` widens to an observe-only `ToolActivity` arm and a computer-use leg, an `ExecutionContext` that gains `perform`/`observe`, an `ApprovalGate` wrapper, and remote-MCP OAuth 2.1 types with RFC-8707 audience-binding. `implement.baml` is the library code; `usage.baml` runs all four kinds across Anthropic and OpenAI Responses; `evaluation.md` stresses where the type system unifies the taxonomy but leaks the catalog.
