# Evaluation — Enriched outputs: logprobs, citations, grounding

Adversarial read of whether the proposed model expresses enriched, provider-bound output without lying. The defining stress here is **binary, provider-bound capability with no honest fallback**, and **no shared type** across the three "sourced answer" mechanisms. These are all **product sidecars** — the answer AND the enrichment arrive off the same response — so they ride the canonical **`call_with` + `ResponseMeta`** path (a tuple `(T, U)` return on the `HttpProvider` capability — `Provider` itself is a bare marker, see `../provider-as-marker.md`), not a bespoke `Scored$Result<T>` companion per feature. P1 ("`call<T> -> T` is too narrow") is therefore **resolved-with-a-named-mechanism** for everything in this scenario; the residuals are pre-existing tensions (OQ5/P2/aggregate-provenance), not new ones.

## (a) What the proposal reuses unchanged

- **The value+sidecar carrier is the canonical one** (`../value-sidecar-model.md`, _conventions.md "Value + sidecar model"). `call_with<T, U>(prompt, project: (ResponseMeta) -> U) -> (T, U)` lives on the `HttpProvider` capability (`Provider` is a bare marker — `../provider-as-marker.md`), and the enrichment is read by `project`. Logprobs sit on the base `ResponseMeta` interface (`m.logprobs() -> Supported<Logprobs>`); the divergent dimensions (`Cited`/`Grounded`/`Annotated`) are external-impl interfaces over each provider's concrete response, reached by a runtime `match` inside `project`. No `Scored`/`Citable`/`Grounded`/`Annotated` companion *method*, no `*$Result<T>` wrapper — those were the old draft's bespoke `Wrapper<T>` companions, and they are gone.
- **`ResponseMeta` is an interface; providers normalize LAZILY** (§2). `OpenAIResponse`/`GeminiResponse`/`AnthropicResponse` each `implements ResponseMeta` plus the one external dimension they actually have. `m => m.usage()` never parses logprobs; `m => m.logprobs()` never walks citations. The normalizers are co-located with the provider, not in a central struct.
- **"Can't" is the typed `Unsupported`, not a null or a throw** (§4). Anthropic's `logprobs()` returns `Unsupported { reason: "anthropic: no logprobs" }`. The app reads it back as a *value* in the projected `U` and branches on it (`ConfidentClassify`'s `match (scores)`), instead of catching an `Unsupported` thrown sentinel. This is the sharpest improvement over the old draft, where "Anthropic cannot score" arrived as a thrown `baml.errors.Unsupported` on the `CallError` channel — see (c).
- **Capabilities/errors/metadata are ONE mechanism** (§7). The novel dimensions (`Cited`/`Grounded`/`Annotated`) are external-impl interfaces reached by `match` — exactly the capability and error patterns. The "no shared citation type" stays honest: three interfaces, three types, no forced `Citation` supertype.
- **`client` is config-only sugar** (§3). The enriched request knobs (`top_logprobs`, `citations.enabled`, the search tool) are provider-private fields (`want_logprobs`, `want_citations`, …) threaded into `build_request`, NOT per-call companions and NOT app-set client fields beyond the client's own config. The client stays `OpenAI { model, api_key, want_logprobs }`.
- **`parse<T>` generic + provider-private wire code, now joined by `meta_of`** (§2). Each `Body` is the provider's concrete response type (`OpenAIResponse`, …); `parse` reads the value, `meta_of` returns the same object as `ResponseMeta`. The four structured encodings and the enriched readers (`*_read_logprobs`, `anthropic_read_citations`) sit beside each other. One interface, divergent bodies.
- **`Fallback` forwards `call_with` structurally** (§1). The old draft needed a bespoke `implements Scored` arm (a for-in/match/continue loop that threw when no member scored). `Fallback` now `implements HttpProvider` and forwards `call_with` (matching each member for `HttpProvider`) with ONE loop, and the per-field "can't" is already typed inside the winner's `ResponseMeta` — the combinator needs no Scored-specific arm at all. The combinator factories (`with_retry`/`fallback_to`/`cached`) are inherited via `requires Provider` (the marker), not redefined. **This is the P1 win the old companion-per-sidecar shape structurally could not get: the sidecar is no longer silently dropped under the combinator.**

## (b) Net-new surface it must add (each tied to a primitive)

- **Tuples `(T, U)` + destructuring — REQUIRED.** `call_with` returns `(T, U)`; the app destructures `let (value, scores): (Sentiment, Supported<Logprobs>) = …` and several functions return tuples directly (`ClassifyOnGemini -> (Sentiment, Supported<Logprobs>)`, `Research$cited -> (Answer, CitedBlock[])`). First-class tuple **types** and tuple **destructuring** are load-bearing here. They are a *shared* dependency (the streaming folds in scenario 04 need them too), not bespoke to metadata — but this scenario does not work without them. (The named `Output<T, U> { value, extra }` struct is the fallback if tuples are rejected, at an ergonomic cost.)
- **Closures as method params** — `project: (ResponseMeta) -> U`, a first-class function value handed into `call_with` and invoked inside the provider/framework body. Every enriched read in usage.baml is a `m => …` closure.
- **`Supported<T> = T | Unsupported`** (one-line std type) — makes "this provider CAN'T score" a typed value distinct from "scores empty this call", carried in `U` rather than thrown.
- **Three external-dimension interfaces** — `Cited`, `Grounded`, `Annotated` (primitive: external-impl `interface` over the concrete response, §7). These cost nothing beyond declaration; they ride the existing match-through-the-response machinery. `logprobs` needs no interface — it is common enough to sit on base `ResponseMeta`.
- **Wire value types** — `Logprobs`/`TokenLogprob`/`TopAlternative`, `DocCitation`/`CitedBlock`, `GroundingChunk`/`GroundingSupport`/`GroundingMetadata`, `Annotation` (primitive: plain `class`). Deliberately NOT unified — four provider-shaped records, no `Citation` supertype. (Unchanged from the old draft; these are the *contents* of the sidecars, whatever carries them.)
- **Per-call error channel** `baml.ExtendUnknownError<baml.errors.CallError>`. The codec path (`build_request`/`send`/`parse`/`meta_of`) and the host readers all close onto the one `CallError` channel via the trailing `catch (e) { _ => throw baml.UnknownError.with_message<…>(e, "…") }`, so foreign `Io`/JSON failures normalize instead of escaping raw — preserved verbatim from the error-model work.
- **Concrete domain errors `implements baml.errors.CallError`** — `AllProvidersFailed` (the `Fallback` exhaustion throw) and the app's `LowConfidence` threshold throw. Both deliberate, branchable typed errors; all classifiers return false.
- **Host boundaries** — `openai_read_logprobs`, `gemini_read_grounding`, `anthropic_read_citations`, etc. (primitive: `$rust_io_function`), genuine transport/codec boundaries.

## (c) Where it is awkward, leaky, or unresolved

- **The OQ5/P2 weakness moves from a THROW to a typed `Unsupported` value — better, but still runtime.** `client GptScored()` returns the existential `Provider`, so "can this client give me logprobs?" is answered at runtime. Swap `GptScored()` for `Claude()` in `Classify` and `ConfidentClassify` still compiles AND still runs — `m.logprobs()` projects `Unsupported`, and the app's `match (scores)` takes the `Unsupported` arm. This is strictly more honest than the old draft (which threw `baml.errors.Unsupported` on the `CallError` channel, conflating "this provider can't" with "this call failed"): per-field absence is now a typed **value** the caller branches on, not a thrown sentinel. But *which* dimensions a client supports is still a **runtime promise** — never the static type of the client. For a feature whose whole premise is "Anthropic has no path," compile-time refusal would be the honest contract, and the existential `client` return cannot give it (P2, localized to metadata; OQ#5). The escape hatch (drop `client`, write `function … -> OpenAIResponse`) recovers static precision but loses provider-swap and combinators — the portability this set is meant to show.

- **Fallback aggregate = the winner's view only.** `project` runs over ONE `ResponseMeta` — the member that won. If `Resilient()` routes past Anthropic to OpenAI, you get OpenAI's logprobs; but if Anthropic *wins*, `m.logprobs()` is `Unsupported` even though a later OpenAI member could have scored — `Fallback` does not re-route to satisfy a projection. And the tokens burned on members that failed first (you paid for them) have nowhere to go: the product shape carries the winner's view, not the chain's. Same aggregate-provenance gap as the error side; pre-existing, not introduced here.

- **The escape hatch rides OQ5 wrapper-transparency.** `m => match (m) { let o: OpenAIResponse => baml.json.from_json<OpenAIWire>(baml.json.parse(o.raw.text())).usage.prompt_tokens, _ => … }` reaches a provider-only raw field (decoded with `baml.json.from_json` off `o.raw.text()`, since `Response` has no `json_path`) — but if `m` is a `FrameworkMeta` wrapping the `OpenAIResponse` (timing/replayed layers), the concrete `match` silently misses unless it can probe through the wrapper. Same occlusion as `UnknownError` boxing a concrete error and `Fallback` hiding its member; same cure (expose `inner` / probe the layers, OQ5). `SourcedAnswer`'s `match (m) { let c: Cited => …, let g: Grounded => … }` is the benign form of the same mechanism; the raw-field reach is the load-bearing one.

- **`logprobs` on the base ResponseMeta looks portable but isn't semantically.** OpenAI leaves `avg` null while Gemini fills it (`avgLogprobs`), and token boundaries are tokenizer-bound per model. Both answer `m.logprobs() -> Supported<Logprobs>` with a real value, so they look interchangeable; they are not. The carrier expresses *shape* portability and silently passes through the *semantic* divergence — a real footgun the type system does not catch. (Unchanged by the carrier swap.)

- **No shared citation type is a NON-leak — and the model is honest about it.** `Cited`/`Grounded`/`Annotated` stay three separate dimensions returning three types; there is no portable `.sourced()` projection. An app that wants "sourced regardless of provider" writes the normalization itself (`SourcedAnswer`, matching each dimension in turn inside one `project`). The std lib declines to lie; the cost lands on the app, visibly. The carrier does not *help* you unify what providers refuse to unify — it just stops charging you a bespoke companion method to express each one.

- **`call_with` does not finish the stateful or sum cases — and correctly does not try.** This scenario is *entirely* product sidecars, so the partition costs nothing here: there is no refusal (that would stay on the `throws` channel as `Refused`), no suspend/tool-calls (sentinel returns), no background/batch handle (`submit -> Job<T>`), and the reasoning *text* projection (`m.reasoning()`) hands you display text but does not thread a signed thinking block into the next turn (that is `Continuity`/P4). All of those are deliberately left on their own mechanisms; `call_with` is not widened to absorb them.

## (d) Verdict: **Resolved-with-mechanism (product sidecars), with named residuals**

The value+sidecar carrier absorbs enriched outputs cleanly: logprobs ride the base `ResponseMeta.logprobs()` as `Supported<Logprobs>`; citations/grounding/annotations ride three external-impl dimensions reached by `match` inside `project`; the answer and the enrichment come back as one tuple `(T, U)` from one call, on the `HttpProvider.call_with` capability (`Provider` is a bare marker), so `Fallback` — itself an `HttpProvider` — forwards them instead of dropping them. The bespoke `Scored$Result<T>` / `.logprobs` companion-per-feature shape — the old draft's `Wrapper<T>` — is gone, and with it the silent-drop-under-combinator bug that was the whole point of P1. The honest modeling of Anthropic's missing logprobs is now a typed `Unsupported` **value** in the projected `U` (a branch), strictly better than the old thrown sentinel on the `CallError` channel.

The genuine residuals are all pre-existing tensions, not new ones, and they are named: (1) **per-field absence is still a runtime promise** — `client` returns the existential `Provider`, so "this client can score" is answered by reading `Unsupported` at runtime, never by the static type (P2/OQ#5), now carried as a value rather than a throw; (2) **the Fallback aggregate is the winner's view only** — `project` sees one `ResponseMeta`, with no slot for the chain's burned tokens (aggregate-provenance, same as the error side); (3) **the raw-field escape hatch rides OQ5 wrapper-transparency**; and (4) **`call_with` carries reasoning text but not its threaded-back continuation, and does not touch sums/stateful round-trips** — those stay on `throws`/sentinel/`submit`/`Continuity`. Net-new language surface this scenario forces: **tuples `(T, U)` + destructuring** (REQUIRED; shared with the streaming folds), closures-as-params, and the `Supported<T>` std type. Resolved for the product sidecars, with the seams the rest of the model already owns — not a clean static guarantee, because the one thing this scenario most wants ("this client CAN score") remains a runtime-only fact the existential return cannot promise.
