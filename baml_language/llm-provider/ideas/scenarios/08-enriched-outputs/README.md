# Scenario 08 — Enriched outputs: logprobs, citations, grounding

This scenario stresses the proposal against output enrichment that is **binary and provider-bound**: features one provider exposes and another simply cannot. Logprobs exist on OpenAI and Gemini but **never** on Anthropic; "sourced answers" exist on all three but as three different objects — Anthropic per-document citation spans, Gemini grounding metadata, OpenAI tool annotations — with no shared citation type. Every one of these is a **product sidecar** (the answer AND the enrichment off the same response), so they ride the canonical **`call_with` + `ResponseMeta`** carrier — a tuple `(T, U)` return on the `HttpProvider` capability (`Provider` is a bare marker — `call`/`call_with` belong to the request/response capability, see `../provider-as-marker.md`) — instead of a bespoke `Scored$Result<T>` / `.logprobs` companion per feature. Logprobs sit on the base `ResponseMeta` (`m.logprobs() -> Supported<Logprobs>`, where Anthropic's is the typed `Unsupported` "can't"); the divergent dimensions are **external-impl** interfaces over each provider's concrete response (`Cited`, `Grounded`, `Annotated`), reached by a runtime `match` inside `project`. Because `Fallback` itself `implements HttpProvider` and forwards `call_with` to an `HttpProvider` member, the sidecar survives the route (the P1 win — no silent drop). `implement.baml` is the std-lib provider and combinator code; `usage.baml` is the app code (including the hand-written normalization an app must own because the std lib refuses to unify what providers don't); `evaluation.md` is the adversarial read — P1 is resolved-with-mechanism for these product sidecars, with the named residuals (winner-only Fallback aggregate, per-field absence as a runtime promise, the raw-field escape hatch riding OQ5).
