# Scenario 32 — Observability: spans, cost, wire-vs-UI message

A colleague reading this wants to know whether the Provider/capability model can express "see every model call and tool call as a trace, know its token cost, and ship it to my backend." The answer here: tracing is a `Traced` **combinator** that wraps any `Provider` (beside `Retry`/`Cache`), opening a span per call and forwarding `call`/`stream`/`tools`/`usage` by the same runtime `match` the proposal already uses. The interesting friction is below the seam — usage counts are out-of-band from `call<T>`'s return (forcing a stateful side-channel), span nesting across an agent loop needs the loop to expose a completion hook, native streaming spans need a matchable `StreamLike`, and the wire-message (lean, what the model sees) vs UI-message (rich, persisted + redacted) split has no home in the current model and is added here as app-authored types. `implement.baml` is the std-lib surface (combinator, `UsageReporting`, `Cost`, message types, `TracingContext`); `usage.baml` shows two divergent providers (OpenAI vs Anthropic usage encodings) wrapped with one `.with_traced(...)` line.
