The shared wrapper tests suite is written in BAML. It starts real Rust or packed BAML wrappers in isolated homes, uses an independently compiled configurable `baml-cli` stub, and serves real release manifests and archives over a loopback HTTP server. The fixture helper only prepares OS resources and serves requests; it never invokes the wrapper or installs a managed toolchain for an installation test.

Run `python3 baml_language/wrapper_tests/run` from the repository root. This builds an independent compiler, pack host and stub, snapshots both Rust self-update variants, packs both BAML self-update variants, and runs the same tests against all four candidates. It uses `baml test` to report behavior-focused test names for each candidate, emits explicit capability skip diagnostics, and returns nonzero if any candidate fails. `--filter "toolchain selection"` runs the selection tests; `--filter "checksum"` selects checksum behavior. `--target <triple>` also builds the wrappers and pack host for that platform while retaining an independent native compiler/test runtime.

CI uses `python3 baml_language/wrapper_tests/run --target x86_64-unknown-linux-gnu --profile ci`. The explicit `ci` profile in `baml.toml` keeps high-value end-to-end contracts: selector precedence, project and local paths, bootstrap and offline launches, installation integrity and archive safety, recovery and concurrent installs, selection-preserving management, config validation, JSON status, stdio delegation, self-update and package-manager guidance, and telemetry opt-out and privacy. It runs against both implementations and both self-update variants, with a ten-minute job budget. Exhaustive permutations and intentional network deadline tests remain available by omitting `--profile`; `--filter` can narrow either suite.

For a prebuilt candidate, use `--no-build --candidate '{"label":"baml","command":["/absolute/path/to/baml"],"self_update":true}'`. Repeat `--candidate` to compare implementations or pass a command prefix in `command`. Adapters pass arguments unchanged and do not repair fixtures. Tests live in behavior files under `baml_src/`, such as `selection.baml`, `installation.baml`, and `telemetry.baml`. Each file groups related behavior in a named BAML `testset`, such as `toolchain selection` or `wrapper telemetry`. Every `test` has a descriptive name and shows its fixture setup, wrapper invocation, and assertions together. Tests create their own `root.harness.Fixture.start()` and register cleanup with `defer { fixture.close(); }`; `baml_src/ns_harness/harness.baml` owns the fixture resources and shared assertions. The Python runner sets one `WRAPPER_CANDIDATE` and invokes ordinary `baml test` separately for each wrapper variant. To add coverage, add a descriptive `test` block to the appropriate `testset`; BAML discovers and filters it directly.

For example, a test lives directly in its behavior group:

```baml
testset "toolchain selection" {
    let candidate = root.harness.Candidate.from_environment();

    test "project version overrides global default" {
        let fixture = root.harness.Fixture.start();
        defer { fixture.close(); }
        fixture.project(NEXT_VERSION);
        fixture.check_installed_selection(candidate, NEXT_VERSION);
    }
}
```

The test appears as `root::toolchain selection::project version overrides global default` in `baml test --list` and failure output. Use `--filter "project version overrides global default"` to run that behavior, or `--filter "toolchain selection"` to run its whole group.

Each fixture starts in an unpinned `project/` with global default `0.11.0`. Versions `0.11.0`, `0.12.0`, and `0.13.0` are already installed; canary is recorded at `0.11.0` and nightly at `0.12.0`. Local stubs identify themselves as `project-local-toolchain` under the project root and home, and `working-directory-toolchain` under the nested working directory and outside the project. Tests change this baseline explicitly before invoking a candidate.

Release gates use `--release-artifacts <downloaded-artifacts-dir> --target <triple> --wrapper-version <version>` to test the exact uploaded Rust and BAML archives. The runner requires every variant shipped for that target in `release/platforms.json`, stages each archived executable unchanged, and fails on missing or ambiguous archives. The BAML binaries come from the canonical `baml-wrapper[-no-self-update]-*` archives that publishers consume; Rust reference binaries use `baml-wrapper-rust[-no-self-update]-*` and are never published. The harness, compiler, and fixture stub are still built independently.

Coverage includes selector precedence and project discovery, local paths, installation and recovery, management, version reporting, configuration validation, JSON status, passive freshness, wrapper replacement, argument validation, and standard-stream delegation. Delegation checks the full new invocation list, identity, argument array, cwd, and direct-CLI guard. Installation checks release requests and installed metadata; management checks selection changes and subsequent launches. Telemetry tests cover independent PostHog events, opt-out, retries, queue recovery, privacy, and operation outcomes; candidates enable this capability with `"posthog": true`.

Capability requirements are ordinary conditions in the enclosing `testset`. Unsupported tests are excluded during discovery with a `SKIP` diagnostic, so the passed count includes only tests that actually ran. Windows paths, suffix handling and replacement run on Windows. Symlink tests require privileges on Windows and are explicitly excluded there. POSIX permissions are tested on POSIX. Self-update cases are selected by the candidate's build capability; replacement always operates on a fixture copy. Unsupported-host diagnostics are covered by the platform resolver's unit tests, since release candidates are built only for supported hosts. CI and release wrapper gates run only `x86_64-unknown-linux-gnu` on `blacksmith-16vcpu-ubuntu-2404`; the other platforms are disabled to keep the gate below ten minutes. Release artifact production still follows the complete platform contract.

The root `.envrc` enforces the PostHog opt-out in CI after machine-specific settings load. The reusable wrapper test workflow, local runner, compiler/test harness, and fixtures disable BCS recording with `BAML_TELEMETRY=off` and `BAML_WRAPPER_BCS_TELEMETRY=off`. The runner and fixtures remove inherited `BOUNDARY_*` settings and use `BOUNDARY_API_KEY=local`, so saved credentials and embedded release tokens cannot send test recordings to production. This applies to locally built candidates and the exact uploaded release binaries. `DO_NOT_TRACK=1` separately disables PostHog by default. PostHog tests opt in only against the fixture’s loopback capture server while leaving BCS recording disabled. The Rust-only BCS probe explicitly targets the same loopback server. Capture assertions cover both wrapper implementations and self-update variants.

Wrapper build-version source-generation contracts run with `python3 -m unittest discover -s baml_language/wrapper_tests -p test_build_versions.py -v`, and automatically in the shared runner when building candidates. The fake build compiler deliberately reports a version unrelated to this checkout, verifies recording/PostHog opt-outs, and accepts a non-executable foreign target host. Tests cover wrapper release overrides/defaults and reject unrecognized compiler version output before packing.

Run `python3 baml_language/wrapper_tests/verify_version_tags.py --cli /absolute/path/to/baml-cli --pack-host /absolute/path/to/matching/baml-pack-host` on a POSIX host for the packed-wrapper recording test; the shared runner also invokes it when building native candidates on POSIX. It packs the current worktree twice, verifies the release override and default, and queries persisted span/process metadata for help, a parsing error, older/newer delegated CLI fixtures, and the telemetry helper. It checks version inheritance, caller metadata/distinct identity, unchanged local `baml.ctx.is_ci` values, the actual entry-versus-main/process attachment scope, unchanged version display, no extra delegated CLI invocations, PostHog opt-out, and recording-off behavior. Unlike the shared suite, these explicit local-only fixtures enable `BAML_TELEMETRY=medium` with `BOUNDARY_API_KEY=local` and a loopback endpoint; `DO_NOT_TRACK=1` remains set. No credentials, authentication commands, or release downloads are used. Logs, binaries, SQL results, and recordings remain in the printed temporary evidence directory; `--evidence-dir` selects a fresh private directory explicitly. The supplied native compiler and pack host must have matching fingerprints; the script does not build or modify runtime sources.

Known contract gaps use `with root.harness.failure_intended("recorded failure message")` on the individual test, with a comment explaining the gap and requiring the marker to be removed once fixed. The runner accepts only that failure, reports `XFAIL`, and rejects an unexpected pass, so later PRs must flip fixed tests back to asserting expected behavior. Fixture errors and unrelated failures remain failures.
