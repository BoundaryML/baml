# BAML Language changelog

This changelog covers the independent `baml_language` release line. It does not describe releases of the main BAML toolchain.

## [0.17.0](https://github.com/BoundaryML/baml/compare/baml-language-0.16.0...baml-language-source-c0153b20108bc428b77a53128b9a59ddeb4e2b42) - 2026-08-14

### Features

- Added reflection specialization for generic functions: `baml.reflect.Package.functions()` lists every declared function, and `baml.reflect.function.Type` gained `is_generic()`, `generic_params()`, `specialize(args)`, and `get<F>()`, so a generic function or one of its generated companions can be bound to runtime-minted type arguments and invoked through reflection. ([#4519](https://github.com/BoundaryML/baml/pull/4519)) - Antonio Sarosi
- Accepted an infinite `while` loop as a divergence form: a loop whose condition is statically `true` and whose body holds no `break` bound to it now satisfies E0113, so `let … else { while (true) {} }` compiles. ([#4493](https://github.com/BoundaryML/baml/pull/4493)) - Antonio Sarosi
- Added read-only `baml.AnyClass` narrowing and reflection for static and runtime-minted class values, with value-bound field handles and catchable typed reads. ([#4491](https://github.com/BoundaryML/baml/pull/4491)) - Antonio Sarosi
- Added runtime reflection and type construction, including compiling and mounting packages, invoking reflected callables, and isolating dynamic work in sessions. ([#4325](https://github.com/BoundaryML/baml/pull/4325)) - Antonio Sarosi
- Added native BAML clients for OpenAI, Anthropic, Google, Vertex AI, AWS Bedrock, Azure, Ollama, OpenRouter, and Vercel AI Gateway, including typed streaming, media outputs, AWS SigV4, and Google Cloud authentication. ([#4430](https://github.com/BoundaryML/baml/pull/4430)) - aaronvg
- Added `baml.sys.pid()`, `baml.fs.chmod()`, and `baml.fs.symlink()`. ([#4427](https://github.com/BoundaryML/baml/pull/4427)) - 2kai2kai2
- Added `baml.crypto.*` APIs for SHA-256 hashing, authenticated encryption, and key generation. ([#4431](https://github.com/BoundaryML/baml/pull/4431)) - 2kai2kai2
- Added `baml toolchain pin <canary|nightly|version|path>` to select a project-local toolchain in the nearest `baml.toml` ([#4386](https://github.com/BoundaryML/baml/pull/4386)) - Sam Lijin
- Added arithmetic across `baml.time` values ([#4366](https://github.com/BoundaryML/baml/pull/4366)) - 2kai2kai2
- Added `assert.is_type<T>(value)` and improved assertion failure formatting  ([#4388](https://github.com/BoundaryML/baml/pull/4388)) - 2kai2kai2
- Added integer and bigint bitwise operators (`&`, `|`, `^`, `<<`, and `>>`), including mixed `int`/`bigint` widening, and added generic `baml.ops.Index` support for arrays, string-keyed maps, and `uint8array`. ([#4301](https://github.com/BoundaryML/baml/pull/4301)) - Avery Townsend
- Enabled advertised LSP code-action support so spec-compliant editors can request BAML code actions, including “Open in Playground.” ([#3358](https://github.com/BoundaryML/baml/pull/3358)) - Miguel F. Serna

### Breaking and compatibility changes

- `baml.reflect.Package.functions()` now lists unspecialized generic functions, which it previously omitted, and `baml.reflect.function.Type.params()` / `return_type()` now declare `throws baml.reflect.errors.CompilationError`: a generic descriptor has no signature to report until `specialize` supplies its type arguments. ([#4519](https://github.com/BoundaryML/baml/pull/4519)) - Antonio Sarosi
- Renamed `baml.reflect.class.Field.read<T>()` to `value<T>()`. ([#4493](https://github.com/BoundaryML/baml/pull/4493)) - Antonio Sarosi
- Renamed `openai.OpenAiClient` to `openai.ResponsesClient`. ([#4430](https://github.com/BoundaryML/baml/pull/4430)) - aaronvg
- Improved the string stdlib APIs: renamed `String.char_at` to `String.at`, kept negative indexing, and made out-of-range access return `null`; made `String.code_point_at` return `null` out of range; removed `String.matches` in favor of `String.includes`; renamed `String.substring` to `String.slice`; and added `String.last_index_of`. ([#4433](https://github.com/BoundaryML/baml/pull/4433)) - 2kai2kai2
- Drop support for Jinja templates: BAML now has TS-style template literals that are much easier to use. ([#4367](https://github.com/BoundaryML/baml/pull/4367)) - Avery Townsend
- LLM function fields now require colon-delimited `client:`, `prompt:`, and `tools:` syntax. ([#4317](https://github.com/BoundaryML/baml/pull/4317)) - Vaibhav Mittal
- Rewrote the type checker to enable more powerful type inference ([#4301](https://github.com/BoundaryML/baml/pull/4301)) - Avery Townsend

### Fixes

- Extended the inline `unreflect(value)` escape rule (E0168) to the two published types it did not read: the error a callee can throw — whether the `throws` clause was written or inferred — and an optional-chained call, where `?.` republishes the call's result as a nullable. `risky<unreflect(t)>(v)` on a callee that can throw `Boom<T>`, and `x?.m<unreflect(t)>()` on a nullable receiver whose callee returns `T`, are refused with the same suggestion to name the type first (`type Out = unreflect(value)`), and a slot that escapes through more than one published type is reported once. Both arms read the published type, so an error typed by the parameter itself (`throws T`), a chained call whose result never mentions it (`-> bool`, `-> Wrapper<unknown>`), a call in argument position inside a chain, and a `?.` link whose receiver is not nullable are all unaffected, as is every shape #4518 accepted. ([#4530](https://github.com/BoundaryML/baml/pull/4530)) - Antonio Sarosi
- Fixed a compiler abort (`type variable not found in type args`) on the rewrite E0168 suggests: a `type Out = unreflect(value)` binding used on a callee that can throw a type mentioning its parameter left that block-scoped name in the caller's inferred `throws`, which reached lowering with nothing to bind it to. The effect a block publishes is now erased like its value, so such a caller compiles and publishes `Boom<unknown>`, and E0096 quotes that instead of the internal name. ([#4530](https://github.com/BoundaryML/baml/pull/4530)) - Antonio Sarosi
- Extended the inline `unreflect(value)` escape rule (E0168) to the two published types it did not read: the error a callee can throw — whether the `throws` clause was written or inferred — and an optional-chained call, where `?.` republishes the result as a nullable. `risky<unreflect(t)>(v)` on a callee that can throw `Boom<T>`, and `x?.m<unreflect(t)>()` on a nullable receiver, are refused with the same suggestion to name the type first (`type Out = unreflect(value)`), and a slot that escapes through more than one published type is reported once. An error typed by the parameter itself (`throws T`), a call in argument position inside a chain, and a `?.` link whose receiver is not nullable are unaffected, as is every shape #4518 accepted. ([#4530](https://github.com/BoundaryML/baml/pull/4530)) - Antonio Sarosi
- Made an assignment inside a `reflect.Session` type-check against its binding, the way ordinary code does: `s.eval("let n = 5")` followed by `s.eval("n = \"seven\"")` is now the same compile error BAML gives anywhere else, instead of rebinding at another type and failing later in the VM with an uncatchable internal error. Compound assignments are checked through the ordinary road too. Re-declaring with `let` at a new type stays legal — it is a new binding, exactly as shadowing works in ordinary code — and assignments at the binding's own type are unchanged. One previously accidental case changes with it: `n += 1.5` on an `int` binding used to commit the float and read back `6.5`, and now compiles and fails at runtime exactly as the same line does in ordinary BAML. ([#4531](https://github.com/BoundaryML/baml/pull/4531)) - Antonio Sarosi
- Made a `let` binding that lives in a global — a Session's top-level bindings and every `client` declaration — behave like an ordinary binding. A method call on one now reaches its receiver instead of failing with an internal `got any` error: `MyClient.id()` in ordinary BAML, and `n.abs()`, `text.to_upper_case()`, `v.length()`, `m.keys()`, a session class's own method and a reflection handle's `fields()` inside a Session. Field access and indexing on such a binding are unchanged. Separately, a Session's `let` now widens a fresh literal initializer to its base type, so `s.eval("let n = 5")` binds `int` rather than the literal type `5`. Two consequences of that are deliberate and visible: a match covering only the literal is now non-exhaustive (and a complete `true`/`false` match on a bool binding is now legal), and an eval contract naming the literal type (`s.eval<5>("n")`) no longer accepts the widened binding. Interface-dispatched methods on such a binding (`n.compare(m)`) reach a separate pre-existing defect and fail with an internal error where they previously failed to compile. ([#4529](https://github.com/BoundaryML/baml/pull/4529)) - Antonio Sarosi
- Fixed a class or enum from `reflect.Package.compile` losing its identity inside an interface method: `type.of<T>()` in an implements block or an inherited default method is now the same `type` value the caller passed in, so a lookup keyed by type finds its entry instead of silently missing. Two compiled packages that each declare `Item` now each keep their own, and neither answers for the other; a statically declared class of the same name is unaffected, as before. Declarations made inside a `Session`, and derived types (`t.array()`, `type.meta(…)`), are unchanged. Nothing about how a type prints changes — diagnostics, `describe`, `to_baml()`, and the `ctx.output_format` schema all still show the name the source wrote. ([#4536](https://github.com/BoundaryML/baml/pull/4536)) - Antonio Sarosi
- Carried a constructed type's identity through interface dispatch: `type.of<T>()` inside an implements-block or inherited default method is now the exact `type` value the caller minted for a `reflect.class.new` or `reflect.enum.new` declaration, instead of an `==`-distinct re-derivation of the same type. Identity-keyed patterns — a registry keyed by type, a comparison against a stored type — match inside an impl body instead of silently missing. Statically instantiated type parameters, derived types (`t.array()`, `type.meta(…)`), and declarations from a compiled `reflect.Package` keep re-deriving their value, so they are unaffected. ([#4516](https://github.com/BoundaryML/baml/pull/4516)) - Antonio Sarosi
- Rejected an inline `unreflect(value)` type argument whose runtime type would escape into the expression's published type — `Agent<unreflect(t)>.new(...)`, `Holder<unreflect(t)> { ... }`, any callee returning `Wrapper<T>` or `T[]` — with E0168, which suggests naming it first (`type Out = unreflect(value)`). The class-literal spelling had reached MIR lowering with an error-recovery type argument and panicked. Results typed by the parameter itself (`sap.parse<unreflect(t)>`, `Fn$parse<unreflect(t)>`) and results that never mention it (`Fn$render_prompt<unreflect(t)>`) are unchanged. ([#4518](https://github.com/BoundaryML/baml/pull/4518)) - Antonio Sarosi
- Fixed optional-chained method calls dropping their type arguments: `x?.m<T>()` — along with inferred, class-generic, and interface-dispatched forms — now seeds the callee's type-argument frame exactly like `x.m<T>()` instead of failing at runtime with an internal frame type-arg error. An optional-chained call to a builtin I/O method (`file?.text()`) also takes the same inline sys-op path as the plain spelling, so its omitted defaulted arguments are materialized rather than reaching the engine unset. ([#4495](https://github.com/BoundaryML/baml/pull/4495)) - Antonio Sarosi
- Rejected class-literal construction of the builtin companion carriers (`baml.Int`, `baml.Map`, `baml.String`, and the other zero-field method carriers) with E0166 instead of building a meaningless empty instance; `baml.Map {}` and `baml.Array {}` had reached MIR lowering with unsolved phantom type arguments and panicked. ([#4493](https://github.com/BoundaryML/baml/pull/4493)) - Antonio Sarosi
- Rejected non-data LLM output schemas with catchable E0164 diagnostics instead of aborting or silently omitting the schema; this intentionally makes previously degraded renders for fields such as `uint8array`, `type`, and mixed non-data unions fail loudly. ([#4470](https://github.com/BoundaryML/baml/pull/4470)) - Antonio Sarosi
