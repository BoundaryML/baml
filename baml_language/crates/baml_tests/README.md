# BAML compiler tests

This crate contains compiler pipeline snapshots, focused unit and integration tests, runtime tests, incremental-query tests, and compiler/VM benchmarks.

## Project-driven snapshot tests

`build.rs` discovers projects one directory below one of these required tiers:

| Tier | Required behavior | Generated phases |
|---|---|---|
| `broken_syntax` | At least one parse error | lexer, parser, diagnostics |
| `diagnostic_errors` | Valid syntax with at least one semantic error | lexer, parser, HIR, TIR, diagnostics, formatter |
| `compiles` | Compiles without errors | all compiler phases and formatter |
| `passing` | Compiles and is suitable for passing runtime coverage | all compiler phases and formatter |
| `passing_llm` | Compiles and contains LLM-oriented passing coverage | all compiler phases and formatter |

Add a fixture under the tier that expresses its expected outcome:

```bash
mkdir -p crates/baml_tests/projects/compiles/my_test
printf 'class Foo {}\n' > crates/baml_tests/projects/compiles/my_test/main.baml
cargo test -p baml_tests compiles::my_test::
```

The generated module path includes both tier and project. Snapshot files are written to `crates/baml_tests/snapshots/<tier>/<project>/`.

Every tier snapshots lexer, parser, and diagnostics output. Higher tiers add HIR/TIR and, for compiling tiers, MIR and bytecode. Projects whose name starts with `parser_` also get incremental parsing, node-reuse, and lossless-tree tests.

## Running tests

```bash
# Entire crate
cargo test -p baml_tests

# One generated project
cargo test -p baml_tests compiles::my_test::

# Accept or review pending snapshots from baml_language/
cargo insta accept --all
cargo insta review
```

`src/generated_tests.rs` is generated by `build.rs`; do not edit it directly.

The exported `baml_test!` and `baml_test_optimized!` macros are for async VM execution tests in Rust. They compile and run inline BAML and return the bytecode/result pair; they do not create the project-driven compiler snapshots described above.
