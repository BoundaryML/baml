# Go smoke for the BEP phase 1 reference

A minimal Go module that consumes the SDK generated from `../baml_src`
(the `[generator.go]` section in `../baml.toml`) and drives the live
Claude Code client end to end.

## Layout

- `baml_sdk/` — generated by `baml-cli generate`; do not edit.
- `live_claude_code_test.go` — the tests: the `json` ↔ `any` mapping
  offline, and the live Claude Code agent loop.
- `go.mod` — points `github.com/boundaryml/baml-go` at the in-repo
  runtime via a `replace` directive.

## Running

```bash
# once, from the workspace root: the native runtime the Go SDK loads
cargo build -p bridge_cffi

# regenerate the SDK after changing baml_src
(cd .. && ../target/debug/baml-cli generate)

# offline tests (the json/any demo)
BAML_RUNTIME_PATH=../../target/debug/libbridge_cffi.dylib go test -short -v ./...

# everything, including the live Claude Code run (uses the CLI's own login)
BAML_RUNTIME_PATH=../../target/debug/libbridge_cffi.dylib go test -v ./...
```

## What the tests show

- `json` maps to `any` in Go: functions returning `json` return `any`
  (objects decode as `map[string]any`, numbers as `int64`/`float64`),
  and `json` parameters accept plain Go values.
- Two known gaps, each with a task filed: objects encoded from Go do
  not yet match BAML's `map<string, json>` typed patterns (so
  `baml.json.path`/`path_or` fall back; `baml.json.field` and
  `stringify` work), and BAML `log.*` output is dropped at the SDK
  bridge boundary (the CLI's `--logs INFO` stream does not exist here).
- The live test runs the whole phase 1 loop from Go: the `Agent`
  runner, the journal, the outcome envelope, and the `claude` CLI as
  the client, with BAML tools executing in-process.
- Go callbacks cross into BAML: `live_claude_code_observed` takes an
  `on_event` observer, and the generated binding accepts a plain
  `func(string, any) baml_go.Null` — BAML calls back into Go for every
  journal event as it appends, with the payload crossing as
  `json` → `any`. This is how a host watches a run live despite the
  log-bridge gap above.
