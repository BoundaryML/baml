The shared wrapper conformance suite is written in BAML. It starts real Rust or packed BAML wrappers in isolated homes, uses an independently compiled configurable `baml-cli` stub, and serves real release manifests and archives over a loopback HTTP server. The fixture helper only prepares OS resources and serves requests; it never invokes the wrapper or installs a managed toolchain for an installation test.

Run `python3 tools/wrapper-e2e/run` from the repository root. This builds an independent compiler, pack host and stub, snapshots both Rust self-update variants, packs both BAML self-update variants, and runs identical scenarios against all four candidates. It reports PASS, FAIL or SKIP for each scenario and implementation and returns nonzero on any failure. `--filter S12` selects IDs by substring. `--target <triple>` also builds the wrappers and pack host for that platform while retaining an independent native compiler/test runtime.

For a prebuilt candidate, use `--no-build --candidate '{"label":"baml","command":["/absolute/path/to/baml"],"self_update":true}'`. Repeat `--candidate` to compare implementations or pass a command prefix in `command`. Adapters pass arguments unchanged and do not repair fixtures. The `baml_src/tests.baml` entry points also expose each scenario to `baml test` using the same environment variables set by the runner.

Scenario IDs follow the wrapper test catalog: S covers precedence and discovery, L covers local paths, I covers installation and recovery, M covers management, V covers version reporting, E covers configuration/state errors, and W covers wrapper replacement. F adds argument rejection and stdio regression cases, including simultaneous large stdin/stdout/stderr transfers and non-UTF-8 bytes. Every delegation checks the full new invocation list, identity, argument array, cwd and direct-CLI guard. Installation assertions check release requests and installed metadata. Management assertions check selection changes and subsequent launches.

Windows paths, suffix handling and replacement run on Windows. Symlink tests require privileges on Windows and are explicitly excluded there. POSIX permissions are tested on POSIX. Self-update cases are selected by the candidate's build capability; replacement always operates on a fixture copy. I20 requires a binary built for an unsupported host and is explicitly excluded from the supported-target matrix. The platform resolver's unsupported-target unit tests cover its diagnostic. All release targets, including both Linux libc variants and both Windows architectures, are scheduled by `.github/workflows/wrapper-e2e.yaml` using the repository platform contract.
