# baml-bench — the BAML Adherence Score

The next stage of the benchmarking system: replace the *feeling* of slop with a measurable question — **is this codebase using BAML's primitives the way we designed them to be used?**

This is a working, deterministic implementation, written in BAML itself (the grader for BAML, written in BAML, gradeable by itself). LLM stages follow the agent-tries-baml pattern: typed BAML functions on an anthropic client pointed at the claude-proxy (`/v1/messages` fulfilled by `claude -p`).

## Contents

| Path | What it is |
|---|---|
| `baml_src/` | The pipeline (pure BAML, pinned fleet toolchain 0.12.2-nightly.20260624.a) |
| `design-principles.md` | 144 principle cards distilled from all 50 BEPs — the grading corpus (127 gradeable by status weight) |
| `adherence-algorithm.md` | The algorithm spec the code implements |
| `data/beps/` | All 50 BEPs (bodies + comment threads) pulled from beps.boundaryml.com's Convex backend |

## Usage

**As a CLI** — `baml pack` builds a standalone binary with the 144-card catalog embedded (`baml_src/catalog_embed.baml`, generated by `scripts/embed_catalog.py`), so it runs from anywhere with no repo checkout:

```bash
cd tools/baml-bench
baml pack Bench -o baml-bench --output-format debug

export LLM_BASE_URL=http://<claude-proxy>   # omit to hit api.anthropic.com directly
export LLM_API_KEY=<proxy token or real key>

./baml-bench --target <baml-project-to-inspect>
# prints the full report in the terminal, and writes
#   <target>/.baml-bench/report.md
#   <target>/.baml-bench/report.json
#   <target>/.baml-bench/cache/        (the reproducibility cache)
# optional: --out <dir> to relocate output, --catalog <md> to override the embedded catalog
```

**Dev entrypoints** (from this directory):

```bash
# deterministic stages only — no LLM, no env needed
baml run -f Scan  -- Scan  --target ../agent-tries-baml
baml run -f Cards -- Cards --catalog design-principles.md

# full graded run with explicit paths
baml run -f Run -- Run --target <project> --out ./out --catalog design-principles.md

baml test        # 11 token-free tests (chunker, cards, evidence gate, cache replay, report)
```

After editing `design-principles.md`, regenerate the embedded copy with `python3 scripts/embed_catalog.py` and repack.

## Pipeline (baml_src/, one file per stage)

```
chunker.baml       (a) column-0 decl scanner + brace/string/comment state machine -> Chunk[]
interactions.baml  (b) identifier scan -> Edge[] (calls / uses_type / exercises)
cards.baml         (0) design-principles.md -> PrincipleCard[] (status -> weight)
llm.baml           (c+d) AnalyzeChunk  intention + routing MERGED (one Haiku call/chunk)
                   (e) GradeCards       ALL routed cards graded in one Sonnet call/chunk
                   (f) RefuteFinding    skeptic pass on every grade <= 4
                   (g) ScanOmissions    codebase-level "never reached for the primitive"
report.baml        (h) weighted aggregation -> report.md + report.json + slop report
cache.baml         content-addressed judgment cache (sha256 via openssl)
main.baml          Scan / Cards / Run entrypoints
tests/             token-free unit tests + SeedSmoke offline harness
```

## Where the determinism comes from

0. **Spawn worker pool.** `BENCH_CONCURRENCY` green threads (default 16, max 64) pull chunks from a shared queue, each carrying its chunk end-to-end (analyze → grade → refute) — no wave barriers, no phase barrier; a slow chunk never stalls the pool. The queue counter is safe because green threads are cooperative (`take()` has no await point). Ordering can't affect results: cache keys depend only on inputs, and all aggregation happens on sorted collections (verified byte-identical across runs).
0. **Merged calls.** Intention+routing are one `AnalyzeChunk` call, and all of a chunk's routed cards are graded in one `GradeCards` call — the chunk source rides in each prompt once instead of once per stage/card (~2-4x fewer calls).
0. **Tiered models.** Intention + routing (once per chunk, high volume) run on Haiku (`GraderFast`); grading, refutation, and the omission scan run on Sonnet (`Grader`). The model id is baked into each stage's cache-key tag, so swapping a tier invalidates exactly that stage's cached judgments.
1. **Stages (a), (b), (0), (h) are pure code** — no LLM, sorted iteration everywhere (chunks by file+line, edges by endpoint, cards in document order, findings by chunk×card).
2. **Content-addressed cache.** Every judgment is stored under `sha256(prompt_version + stage + exact inputs)`. Identical inputs never reach the model twice, so a completed run replays **byte-for-byte** (verified: two `Run`s diff clean), and re-runs after edits only re-judge changed chunks. Ship the `out/cache/` directory to make a run reproducible anywhere.
3. **Deterministic gates on LLM output.** Evidence quotes are checked mechanically against the chunk source (whitespace-normalized substring) — a grade whose quote isn't real is neutralized. Routed card ids are filtered to the actual catalog. Grades are clamped 1–10.
4. **temperature 0** is requested on the client; with the proxy running `claude -p` that's best-effort, which is exactly why the cache, not the sampler, is the reproducibility mechanism.
5. **`prompt_version()`** (types.baml) participates in every cache key — editing any prompt invalidates stale judgments instead of silently mixing eras.

## Offline end-to-end proof

`tests/smoke.baml` mirrors `Run`'s cache-key derivation and seeds canned judgments, so the whole pipeline (route → grade → evidence gate → refutation → report) runs with zero LLM calls:

```bash
baml run -f SeedSmoke -- SeedSmoke --target <fixture> --out <out> --catalog <mini-catalog>
baml run -f Run       -- Run       --target <fixture> --out <out> --catalog <mini-catalog>
```
