# intentionbench — the slop-killer-compiler

The benchmarking system's second generation: replace the *feeling* of slop with a measurable question — **is this codebase using BAML's primitives the way we designed them to be used?** — asked over an **AST-like hierarchy of the whole codebase**, not a flat chunk list.

Written in BAML itself (the grader for BAML, written in BAML, gradeable by itself). LLM stages follow the agent-tries-baml pattern: typed BAML functions on an anthropic client pointed at the claude-proxy (`/v1/messages` fulfilled by `claude -p`).

## The model

1. **CodeBlock tree** (`scanner.baml`, `tree.baml`) — deterministic recursive scan: one `PROGRAM` superblock → file blocks → declaration blocks (functions, LLM functions, classes, enums, interfaces, type aliases, tests, clients) → member blocks (fields, variants, params, methods) → `let`-bound variable blocks. Stable ids (`PROGRAM`, `F:<path>`, `D:<path>:<Name>`, `M:…:<Owner>.<member>`, `V:…#<n>` for shadowing).
2. **InteractionBlocks** (`interactions.baml`) — first-class relations, all deterministic: **by_depth** (containment, every child↔parent), **reference** (static identifier scan: `calls`/`uses_type`/`exercises`), **by_level** (sibling pairs under a common parent, capped at 30/parent — statically-evidenced pairs ranked first; `BENCH_PAIR_CAP` overrides).
3. **Intentions on everything** (`intent.baml`) — Haiku-tier, bottom-up: leaves batched ONE call per parent; each non-leaf block's call is grounded in its children's already-inferred intentions (so cache keys are transitively content-addressed); interaction intentions batched per parent group. `{goal, mechanism}` for blocks, `{relationship, purpose}` for interactions.
4. **Routing** (`routing.baml`) — fully deterministic, no LLM router: static/gate keyword rules per card; the no-rule semantic bucket routes to non-leaf blocks only; `interaction_rules()` routes relational cards by edge kind. Borderline routes are arbitrated inside the grading prompt (inapplicable → neutral, empty evidence → mechanically neutralized).
5. **Grading** (`grade.baml`) — Sonnet-tier `GradeJob`s (one subject × ≤12 cards), anchored 1–10 rubric, verbatim-evidence gate, **parallel** skeptic refutation of grades ≤4, codebase-level omission scan over the decl+file intention table.
6. **Score + report** (`score.baml`, `report.baml`) — `weight = card status × kind_weight × size_factor`; adherence/commission/omission scores, per-principle, per-file, per-kind tables, slop report, and a tree outline of where quality lives.

## Usage

**As a CLI** — `baml pack` builds a standalone binary with the 144-card catalog embedded (`catalog_embed.baml`, generated by `scripts/embed_catalog.py`):

```bash
cd tools/baml-bench
baml pack Bench -o intentionbench --output-format debug

export LLM_BASE_URL=http://<claude-proxy>   # omit to hit api.anthropic.com directly
export LLM_API_KEY=<proxy token or real key>

./intentionbench --target <baml-project-to-inspect>
# prints the full report, and writes
#   <target>/.intentionbench/report.md
#   <target>/.intentionbench/report.json
#   <target>/.intentionbench/cache/     (the reproducibility cache)
# optional: --out <dir>, --catalog <md> to override the embedded catalog
```

**Dev entrypoints** (from this directory):

```bash
# deterministic stages only — no LLM, no env needed
baml run -f Scan  -- Scan  --target <project>       # block tree + interaction counts
baml run -f Cards -- Cards --catalog design-principles.md

# full graded run with explicit paths
baml run -f Run -- Run --target <project> --out ./out --catalog design-principles.md

baml test        # 34 token-free tests (scanner, interactions, routing, intents, grading, score, report)
```

**Concurrency**: `FAST_CONCURRENCY` (intent waves, default 24) and `JUDGE_CONCURRENCY` (grading, default 24) size the two independent worker pools.

After editing `design-principles.md`, regenerate the embedded copy with `python3 scripts/embed_catalog.py` and repack.

## Where the determinism comes from

1. **Stages (a), (b), routing, and (h) are pure code** — same bytes in, same tree/interactions/jobs out; sorted iteration everywhere.
2. **Content-addressed cache.** Every judgment is stored under `sha256(prompt_version + stage@model + exact inputs)`. Identical inputs never reach the model twice, so a completed run replays **byte-for-byte** regardless of pool sizes (verified: repeated `Run`s diff clean under different `FAST_/JUDGE_CONCURRENCY`). Parent intent keys include the child-intent table, so editing a variable re-judges exactly its containment chain.
3. **Deterministic gates on LLM output.** Batched outputs are reconciled against the request (unknown ids dropped, missing filled neutral, grades/confidence clamped, verdicts derived from the grade band). Evidence quotes are checked mechanically against the graded source — a grade whose quote isn't real is neutralized.
4. **temperature 0** is requested; with the proxy running `claude -p` that's best-effort, which is exactly why the cache, not the sampler, is the reproducibility mechanism.
5. **`prompt_version()`** (model.baml) participates in every cache key — prompt edits invalidate stale judgments instead of silently mixing eras.

## Offline end-to-end proof

`tests/smoke.baml` mirrors every cache-key derivation and seeds canned judgments, so the whole pipeline (waves → routing → grading → gates → refutation → omissions → report) runs with zero LLM calls:

```bash
baml run -f SeedSmoke -- SeedSmoke --target fixtures/smoke --out <out> --catalog fixtures/mini-catalog.md
baml run -f Run       -- Run       --target fixtures/smoke --out <out> --catalog fixtures/mini-catalog.md
```

Two such `Run`s must produce byte-identical reports — that's the determinism regression test.
