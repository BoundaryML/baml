Which models write real BAML?

Five models got the same job: build a small BAML project from nothing. A receipt extractor. Types, one LLM function, a couple of pure helpers, tests. None of them had seen the language before. Each got a live baml CLI and 25 turns to learn it — baml describe String to read the stdlib, baml check to find out what the compiler thinks.

Then one grader scored every project. baml-bench chunks the code, routes each chunk against 127 design-principle cards distilled from all 50 BAML Enhancement Proposals, and grades each pair on a 1–10 scale: does this code use the language the way we designed it? Evidence quotes get checked against the source before a grade counts, and every low grade survives a skeptic pass before it reaches this page. Total builder cost for all five runs: $2.24.

Adherence is the weighted 1–10 mean over graded (chunk, card) pairs. Slop counts findings that survived both the evidence check and the skeptic. Live data from the experiments Convex project.

The scoreboard lies if you read it alone

gpt-5-nano took first place. 8.71, zero slop findings, the most code of any model. Its project has 407 compile errors.

It wrote fluent pseudo-BAML. The shapes match what the design cards want, so the grader had nothing to object to, and almost none of it parses. Meanwhile claude-haiku-4-5 came fourth — and haiku is the only model in the table whose project compiles.

So the two numbers measure different skills. Adherence tells you whether the text respects the language's design. Compilation tells you whether the code is real. A model can fake the first one. It can't fake the second. Our takeaway for the benchmark itself: the headline metric should be adherence gated by compilation, and that change is now on the roadmap for baml-bench.

How each model behaved

Method, briefly

The builder loop gives each model two tools: baml <args> (a real CLI in its project directory) and write_file. The task prompt says the model has never seen BAML and should learn it from the CLI before writing code. A hard $10 spend meter prices every API call from actual token usage and kills the whole sweep if crossed. It never got close.

The grader is the same for every model: Sonnet judgments behind a content-addressed cache, temperature 0, evidence quotes verified mechanically against the chunk source. Grader bias is constant across rows, so differences between models are differences in what they wrote.

Caveats worth keeping: one build per model, one task, and every model ran out of turns rather than declaring itself done. Orderings within a point of each other are noise until we run repetitions. The harness makes that cheap — judgments are cached, so a rerun only pays for what changed.
