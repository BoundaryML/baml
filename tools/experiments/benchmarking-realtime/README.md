# voice-agent: gpt-realtime-2.1 + BAML thinker

An instant voice agent using OpenAI's **responder–thinker** realtime pattern:

- **Responder** — `gpt-realtime-2.1` over the GA Realtime WebSocket API. It
  listens, speaks, and has exactly ONE function tool: `delegate(request)`.
- **Thinker** — a BAML (new language) function `handle()`. The realtime model
  passes the user's request verbatim (spelled-out IDs and all); BAML's
  `DecideAction` LLM function SAP-parses the reply straight into a typed union
  `GetWeather | LookupOrder | SetTimer | CreateCalendarEvent | SendMessage | Answer`, executes the tool in BAML,
  and returns a speakable `ToolOutcome`.

Why this beats native JSON-schema function calling: tool selection and argument
extraction happen in one structured decode by a stronger text model, with typed
classes and normalization rules ("a one b two dash c three d four" →
`A1B2-C3D4`, "an hour and a half" → `5400`), while the voice model masks the
latency with a filler phrase (per OpenAI's realtime prompting guide).

## Layout

- `brain/` — BAML project (pinned toolchain `0.12.2-nightly.20260624.a`).
  - `baml_src/types.baml` — the action union + `ToolOutcome`.
  - `baml_src/thinker.baml` — `Thinker` client, `DecideAction`, `handle()`.
  - `baml_src/tools.baml` — executors: live open-meteo weather (with region
    disambiguation), fixture order DB, timer normalization.
  - `baml_src/tests.baml` — deterministic executor tests (`baml test`).
- `server/` — Node/TypeScript app.
  - `baml_sdk/` — generated by `baml generate` (from `brain/baml.toml`).
  - `src/relay.ts` — WebSocket to OpenAI (GA events), delegate→BAML loop.
  - `src/index.ts` — serves the browser voice client at `http://localhost:8787`.
  - `src/cli.ts` — text-mode harness (same session + tool loop, no audio).
  - `src/mock-realtime.ts` — local mock of the GA protocol for keyless testing.
  - `public/index.html` — mic capture (24kHz PCM16 worklet), audio playback,
    transcript + tool log, client-side timer effect.

## Run data

Every turn (arena and benchmark) is logged to the Convex project
`experiments` (boundary team, prod deployment `giddy-coyote-574`), table
`turns`: utterance, per-lane tool calls with raw args and executor payloads,
final text, latency, pass/fail for benchmark cases. Backend source in
`convex-experiments/`; set `CONVEX_URL` to disable or redirect.

## Run

Entrypoints self-load `server/.env` (see `src/env.ts`). If `ANTHROPIC_API_KEY`
is present it wins: the thinker goes direct to `api.anthropic.com`.

```bash
cd server && npm install

# THE ARENA (browser): both agents side by side, one mic/text input
npm start            # then open http://localhost:8788
# "START SESSIONS" opens 2 realtime sessions (baml speaks aloud; native is
# text-only). Tool calls render as cards with args + latency; the benchmark
# scoreboard below is generated from real compare-results*.json runs.

# text mode against the real realtime API (single agent, delegate mode)
npm run text -- "set a timer for twenty five minutes"

# keyless e2e (mock realtime + real BAML thinker)
npx tsx src/mock-realtime.ts &
REALTIME_URL=ws://localhost:8790 OPENAI_API_KEY=mock npm run text -- "..."
```

BAML dev loop: edit `brain/baml_src/*.baml`, then `baml test` and
`baml generate` (from `brain/`). Keep `@boundaryml/baml-core-node` in
`server/package.json` pinned to the exact toolchain version — bytecode is not
compatible across versions.

## Tool-calling comparison (native vs BAML thinker)

`src/compare.ts` runs the same utterances through two session configs against
live `gpt-realtime-2.1` (text mode, one session per mode, shared BAML
executors so only tool selection/arg extraction differs):

- **native** — the standard setup: three JSON-schema tools in `session.tools`,
  the realtime model extracts arguments itself.
- **delegate** — one `delegate()` tool; BAML `DecideAction` selects and
  extracts into the typed union.

Results (2026-07-07, `compare-results*.json`):

| suite | native | delegate (BAML) |
| --- | --- | --- |
| base (7: spelled IDs, spoken durations, disambiguation, no-tool) | 7/7, ~1.7s/turn | 7/7, ~4.8s/turn* |
| hard (5: confusable phonetics, indirect locations, fractions) | 3/5, ~1.8s/turn | 5/5, ~4.5s/turn* |
| adversarial (7: nested math, "zed", nicknames, world knowledge, multi-intent) | 7/7, ~2.0s/turn | 7/7, ~3.7s/turn |

Total: **BAML 19/19, native 17/19.** Both native failures were argument
extraction: "queue five are six dash ess seven tea eight" lost the leading Q
(`5R6-S7T8`), and "weather where the golden gate bridge is" passed
`city="Golden Gate Bridge"` (it recovered with a second tool call).
(*base/hard delegate times used the claude-CLI proxy thinker; the adversarial
run used a direct Anthropic key.)

Run it: `npx tsx src/compare.ts [native|delegate] [hard|adv]` — the mode
filter spends only one API session and merges the other mode from the saved
results file.

## API budget kill switch

Every real realtime session increments `.api-budget.json`; at
`API_CALL_LIMIT` (default 10) the process refuses to connect and exits.
Reset by deleting the file. Mock sessions are free.

## Known upstream issue

`DecideAction$parse` (offline SAP regression testing) throws
`InvalidArgument: "Unions must be flattened"` for any union return type on
0.12.2→0.13.1 nightlies, even though the live LLM path parses unions fine.
Parser tests are omitted until that's fixed.

Second one: the generated TS SDK mis-tags union-typed *parameters* — any
instance passed to `execute_async(action: GetWeather | ... )` is decoded as
the FIRST union variant (`SetTimer` arrives as `GetWeather`, panics with
"Missing field `city`"). Workaround: call the monomorphic executors
(`run_timer_async` etc.), as `relay.ts` does.

Third one: passing an integer-valued JS number (e.g. `1`) into a BAML `float`
field segfaults the `@boundaryml/baml-core-node` binding, while `1.5` crosses
fine. Worked around in `run_medication_wire` (floats ride the TS boundary as
strings and parse inside the VM with `float.parse`).
