# Optimizing Token Usage with TOON

When working with LLMs, token usage directly impacts both cost and latency. BAML provides the `format` filter (use `type="toon"`) to help you reduce token consumption by 30-60% when passing structured data in prompts.

## What is TOON?

TOON (Token-Oriented Object Notation) is a compact data format designed specifically for LLM prompts. It uses:
- Indentation-based structure (like YAML)
- Tabular format for arrays of objects (declare keys once, stream rows)
- Minimal punctuation

## When to Use TOON

### ✅ Use TOON when:
- Passing data to the LLM for analysis
- Working with large structured datasets
- Token costs are a concern
- Handling arrays of similar objects

### ❌ Use standard formats when:
- The LLM needs to return structured data (use standard BAML output types instead)
- Working with external systems that expect JSON
- Data structure is very small (< 100 tokens)

## Basic Example

Let's compare JSON vs TOON for a product analysis task:

### Using JSON (default)

```baml
class Product {
  id int
  name string
  price float
  in_stock bool
}

function AnalyzeProducts(products: Product[]) -> string {
  client GPT4
  prompt #"
    Analyze these products and provide insights:
    
    {{ products }}
    
    Focus on pricing trends and inventory status.
  "#
}
```

When you pass products to this function, they're serialized as JSON:

```json
[
  { "id": 1, "name": "Widget", "price": 9.99, "in_stock": true },
  { "id": 2, "name": "Gadget", "price": 19.99, "in_stock": false }
]
```

**Token count: ~257 tokens** (for a larger dataset)

### Using TOON

Simply add the `format(type="toon")` filter:

```baml
function AnalyzeProducts(products: Product[]) -> string {
  client GPT4
  prompt #"
    Analyze these products and provide insights:
    
    {{ products|format(type="toon") }}
    
    Focus on pricing trends and inventory status.
  "#
}
```

Now the same data is serialized as TOON:

```
[2]{id,name,price,in_stock}:
  1,Widget,9.99,true
  2,Gadget,19.99,false
```

**Token count: ~166 tokens** (35% reduction)

## TOON Options

### Custom Indentation

Control spacing for better readability:

```jinja
{{ products|format(type="toon", indent=4) }}
```

### Alternative Delimiters

Choose the delimiter that works best for your data:

```jinja
{# Comma-separated (default) #}
{{ products|format(type="toon", delimiter="comma") }}

{# Tab-separated (more token savings) #}
{{ products|format(type="toon", delimiter="tab") }}

{# Pipe-separated (best for data with commas) #}
{{ products|format(type="toon", delimiter="pipe") }}
```

### Length Markers

Add length indicators for clarity:

```jinja
{{ products|format(type="toon", length_marker="#") }}
```

Output:
```
#2[2]{id,name,price,in_stock}:
  1,Widget,9.99,true
  2,Gadget,19.99,false
```

## Real-World Use Case: Transaction Analysis

Here's a complete example analyzing financial transactions:

```baml
class Transaction {
  id string
  date string
  amount float
  category string
  merchant string
  status string
}

function AnalyzeTransactions(
  transactions: Transaction[],
  question: string
) -> string {
  client GPT4
  prompt #"
    {{ _.role("system") }}
    You are a financial analyst. Answer questions about transaction data.
    
    {{ _.role("user") }}
    Transaction data:
    {{ transactions|format(type="toon", delimiter="pipe") }}
    
    Question: {{ question }}
  "#
}

test AnalyzeSpending {
  functions [AnalyzeTransactions]
  args {
    transactions [
      {
        id: "tx_001",
        date: "2025-01-15",
        amount: 45.99,
        category: "Dining",
        merchant: "Coffee Shop",
        status: "completed"
      },
      {
        id: "tx_002",
        date: "2025-01-16",
        amount: 120.00,
        category: "Shopping",
        merchant: "Electronics Store",
        status: "completed"
      }
    ]
    question "What's my largest expense category this week?"
  }
}
```

## Token Savings at Scale

The savings compound with larger datasets:

| Data Size | JSON Tokens | TOON Tokens | Savings |
|-----------|-------------|-------------|---------|
| 10 items  | ~500        | ~300        | 40%     |
| 50 items  | ~2,400      | ~1,200      | 50%     |
| 100 items | ~4,800      | ~2,200      | 54%     |

For high-volume applications, this can translate to significant cost savings:
- 10,000 API calls/day @ $0.01/1K tokens
- Without TOON: $48/day = $1,440/month
- With TOON: $22/day = $660/month
- **Savings: ~$780/month**

## Best Practices

### 1. Combine with Other Optimizations

```baml
function SmartAnalysis(data: Dataset[], context: string) -> Analysis {
  client GPT35  // Use cheaper model when appropriate
  prompt #"
    {{ _.role("system") }}
    {{ context|trim }}  // Remove extra whitespace
    
    {{ _.role("user") }}
    Data:
    {{ data|format(type="toon", delimiter="tab") }}  // Use TOON for structured data
    
    Provide a brief analysis.
  "#
}
```

### 2. Use for Arrays, Not Single Objects

TOON provides maximum benefit for arrays:

```jinja
{# Good - array of objects #}
{{ products|format(type="toon") }}

{# Less beneficial - single object #}
{{ user|format(type="toon") }}  // Consider using JSON instead
```

### 3. Choose Delimiters Based on Content

```jinja
{# Data contains commas? Use pipe #}
{{ addresses|format(type="toon", delimiter="pipe") }}

{# Data is mostly numeric? Use tab #}
{{ metrics|format(type="toon", delimiter="tab") }}

{# Default comma works for most cases #}
{{ general_data|format(type="toon") }}
```

## Measuring Impact

Use the BAML Playground to compare token usage:

2. Test it in the playground and note token count
3. Add the `format(type="toon")` filter
4. Compare the new token count

The playground shows you the exact prompt sent to the LLM, making it easy to verify token savings.
