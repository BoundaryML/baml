The `@json` attributes describe how a class looks as JSON, so you don't have to write a `baml.ToJson` or `baml.FromJson` override. `baml.json` follows them with no extra arguments, and so do the `serde` impls of a generated Rust SDK.

`@alias` is different: it's the name a model is shown. Use `@json.rename` for the key your API uses.

## `@json.rename`

Sets the JSON key of a field, or the JSON string of an enum variant.

```baml BAML
class Network {
  vpcId string @json.rename("vpc_id")
}

enum Mode {
  Fast @json.rename("fast-mode")
  Slow
}
```

The field reads from `vpc_id` and writes to `vpc_id`. The name `vpcId` is no longer a JSON key. If a field has both `@alias` and `@json.rename`, its JSON key is the `@json.rename`, and a model's answer may use either.

## `@json.flatten`

Goes on a `map<string, json>` field. The field holds every key no other field took, and writes them next to the other fields.

```baml BAML
class Config {
  id string
  extra map<string, json> @json.flatten
}
```

`{"id": "a", "region": "us"}` reads as `Config { id: "a", extra: {"region": "us"} }` and writes back the same way. If the map holds a key a declared field also writes, the declared field wins and the map entry is skipped.

## `@json.fallback`

Goes on a `map<string, json>` field, and keeps a union open to members you don't know yet. An object no member's literal fields match becomes this class, with the whole object in the field. It writes that object back and nothing else. The class's other fields must be literals, and each one names a key the object must have: `type` below. An object with no `type` is an error, not a `NetworkOther`.

```baml BAML
class UseDefault {
  type "use-default"
}

class ByoVpc {
  type "byo-vpc"
  vpcId string @json.rename("vpc_id")
}

class NetworkOther {
  type "UNKNOWN"
  raw map<string, json> @json.fallback
}

type Network = UseDefault | ByoVpc | NetworkOther
```

| JSON | Reads as |
| --- | --- |
| `{"type": "byo-vpc", "vpc_id": "v"}` | `ByoVpc` |
| `{"type": "future-mode"}` | `NetworkOther` with `raw` holding the object |
| `{"type": "byo-vpc"}` | An error: the tag matches `ByoVpc`, but `vpc_id` is missing |
| `{"kind": "other"}` | An error: there's no `type` |

## `@@json.omit_nulls`

Leaves out the class's fields that hold `null` when it's written. Reading doesn't change: a missing optional field reads as `null`. It applies only to the class's own fields, not to nested classes.

```baml BAML
class Request {
  name string
  note string?

  @@json.omit_nulls
}
```

`Request { name: "a", note: null }` writes `{"name": "a"}`.

## What the compiler rejects

| Mistake | Why |
| --- | --- |
| `@json` attributes on a class that implements `baml.ToJson` or `baml.FromJson` with its own method | The attributes would be ignored |
| `@json.flatten` or `@json.fallback` on anything but `map<string, json>` | The field holds JSON keys and values |
| More than one `@json.flatten` or `@json.fallback` in a class | Only one field can hold the remaining keys |
| `@json.rename` on a `@json.flatten` or `@json.fallback` field | The field has no key of its own |
| A `@json.fallback` class with a field that isn't a literal | JSON doesn't set its other fields |
| A union with a fallback member and another member that can read any object: a class with no literal field, or a map | That member would take every object, so the fallback would never be used |
| Two fields with the same JSON key | One key can't fill both |
