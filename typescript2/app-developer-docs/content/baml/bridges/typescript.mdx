Call BAML from a Node.js application using a generated `baml_sdk` and the `@boundaryml/baml-bridge` runtime. These examples use **Canary** and the generator’s default `preserve-case` naming convention.

## Generate the SDK

Start with a [BAML project](/baml/get-started), then run these commands from its root:

```sh
baml generate add typescript/node
baml generate
npm init -y
npm pkg set type=module
npm install @boundaryml/baml-bridge
npm install --save-dev tsx typescript @types/node
```

The runtime uses ES modules. These commands initialize a new Node.js package; in an existing application, use its ES-module configuration.

Run `generate add` once. It adds a generator to `baml.toml`; `baml generate` writes `baml_sdk/` beside that file. Regenerate after changing BAML source.

Match the runtime package version to the toolchain version printed by `baml --version`. If npm’s default release differs, install that exact version with `npm install @boundaryml/baml-bridge@<version>`.

## Call a function

With `return_number` from [Get started](/baml/get-started), create `app.ts` beside `baml.toml`:

```typescript
import { return_number } from "./baml_sdk/index.js"

async function main() {
  const value = await return_number(42)
  console.log(value)
}

main().catch((error) => {
  console.error(error)
  process.exitCode = 1
})
```

Run it with `npx tsx app.ts`. It prints `42`.

`return_number` returns a promise, so other JavaScript work continues while the call runs, such as when a Node.js server waits for a model response. Import from `baml_sdk/index.js` so the SDK initializes its runtime and type mappings.

## Call synchronously

The Node.js generator also exports a `_sync` variant of each function. It blocks the JavaScript thread until the call finishes and returns the value directly:

```typescript
import { return_number_sync } from "./baml_sdk/index.js"

const value = return_number_sync(42)
console.log(value)
```

Replace `app.ts` with this version and run `npx tsx app.ts` again. It also prints `42`.

Use the `_sync` variant only in scripts and command-line tools where blocking is acceptable.

## Call a model

Add the BAML source from [Classify support tickets](/examples/classify-support-tickets), run `baml generate`, and set `OPENAI_API_KEY` in the server’s environment:

```typescript
import { classify_message, type Category } from "./baml_sdk/index.js"

export async function classify(input: string): Promise<Category> {
  return classify_message(input)
}
```

## Streaming

For an LLM function, the generator also exports a `$stream` function. Read partial values with `next()` until it returns `ai.stream.Done`, then call `final()` for the complete result:

```typescript
import { ai, classify_message$stream } from "./baml_sdk/index.js"

export async function streamCategory(input: string) {
  const stream = await classify_message$stream(input)
  while (true) {
    const partial: unknown = await stream.next()
    if (partial instanceof ai.stream.Done) break
    console.log(partial)
  }
  return await stream.final()
}
```

The blocking twins are `classify_message$stream_sync`, `stream.nextSync()` and `stream.finalSync()`.

Canary’s generated stream type currently omits the `Done` sentinel from `next()`’s return type. The example narrows from `unknown` to check the runtime sentinel.

A partial value can be `null`; it does not mean the stream has ended. Calls and stream reads can fail, so handle rejections at your application boundary.
