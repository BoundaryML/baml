Call BAML from a Node.js application using a generated `baml_sdk` and the `@boundaryml/baml-bridge` runtime. These examples use **Canary** and the generator’s default `preserve-case` naming convention.

## Generate the SDK

Start with a [BAML project](/baml/get-started), then run these commands from its root:

```sh
baml generate add typescript/node
baml generate
npm init -y
npm pkg set type=module
npm install @boundaryml/baml-bridge
npm install --save-dev tsx typescript @types/node
```

The runtime uses ES modules. These commands initialize a new Node.js package; in an existing application, use its ES-module configuration.

Run `generate add` once. It adds a generator to `baml.toml`; `baml generate` writes `baml_sdk/` beside that file. Regenerate after changing BAML source.

Match the runtime package version to the toolchain version printed by `baml --version`. If npm’s default release differs, install that exact version with `npm install @boundaryml/baml-bridge@<version>`.

## Call a function

With `return_number` from [Get started](/baml/get-started), create `app.ts` beside `baml.toml`:

```typescript
import { return_number_async } from "./baml_sdk/index.js"

async function main() {
  const value = await return_number_async(42)
  console.log(value)
}

main().catch(console.error)
```

Run it with `npx tsx app.ts`. It prints `42`.

The Node.js generator exports both `return_number`, which returns synchronously, and `return_number_async`, which returns a promise. Use the async form in a server so a BAML call does not block its JavaScript thread. Import from `baml_sdk/index.js` so the SDK initializes its runtime and type mappings.

## Call a model

Add the BAML source from [Classify support tickets](/examples/classify-support-tickets), run `baml generate`, and set `OPENAI_API_KEY` in the server’s environment:

```typescript
import { classify_message_async, type Category } from "./baml_sdk/index.js"

export async function classify(input: string): Promise<Category> {
  return classify_message_async(input)
}
```

## Streaming

For an LLM function, the generator also exports a `$stream_async` function. Read partial values with `nextAsync()` until it returns `ai.stream.Done`, then call `finalAsync()` for the complete result:

```typescript
import { ai, classify_message$stream_async } from "./baml_sdk/index.js"

export async function streamCategory(input: string) {
  const stream = await classify_message$stream_async(input)
  while (true) {
    const partial: unknown = await stream.nextAsync()
    if (partial instanceof ai.stream.Done) break
    console.log(partial)
  }
  return await stream.finalAsync()
}
```

Canary’s generated stream type currently omits the `Done` sentinel from `nextAsync()`’s return type. The example narrows from `unknown` to check the runtime sentinel.

A partial value can be `null`; it does not mean the stream has ended. Calls and stream reads can fail, so handle rejections at your application boundary.
