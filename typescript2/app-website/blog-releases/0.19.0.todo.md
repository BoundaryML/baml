# Release gates

This checklist is internal and must keep `isPublished: false`, including after the release post is published. All responses below are drafts. No notification has been sent.

- [ ] Confirm the release version and date. `0.19.0` and September 11, 2026 in America/Los_Angeles are provisional. The pinned source still carries the `0.18.0` version stamp.
- [ ] Confirm the release includes `7622555396a99db466afaea09dea2cad259d4033..a748b3a694496fa96b043b4bb03b02b529c95584`. The lower boundary is the latest released canary, `baml-language-0.18.0`; the upper boundary is the fetched and pinned `origin/canary`. Re-audit additional commits if the actual release extends this range.
- [ ] Publish the language artifacts, matching bridges and editor integration through the repository release process, then verify the manifest and install/generate workflow. This preparation task does not publish them.
- [ ] Review the [draft](2026-09-11-baml-0.19.0.md), [validation](../../../docs/changelog-0.19.0-validation.md), and [research](../../../docs/changelog-0.19.0-followup-research.md). Correct the relative review links if moving this checklist.
- [ ] Before publishing the release post with its Linux installer entry, bump the independently versioned wrapper beyond the live 0.2.4 catalog, publish wrapper artifacts containing #4632, and verify bootstrap on Debian Bookworm and Alpine for x86_64 and ARM64. A language-only cut reuses the live wrapper when its version has not changed. If this separate wrapper release is deferred, omit the installer claim and its #4624 notification from this release; do not publish them on the strength of source changes or catalog target names.
- [ ] Publish only the release post after the language release and every claim-specific publication gate above are satisfied. Verify it appears at https://boundaryml.com/changelog and that the internal checklist remains absent from both listing and direct slug lookup.
- [ ] Record the verified wrapper version and bootstrap evidence before publishing either the installer claim or its notification. The live wrapper catalog was `0.2.4` during preparation and advertised GNU/musl artifacts, but its git tag predates #4632. Catalog presence alone does not establish that published binaries contain the fix.
- [ ] Recheck the linked conversations for newer replies, then post each approved draft once after publication. Record the posted URL here. Do not close #4750 or imply that its signed-zero literal aliasing is fixed.
