# Customer handoff: Alien package isolation

Context: [TASK-122](https://app.notion.com/p/409bb2d26216817b8644c6e8462532ef), [original feedback](https://app.notion.com/p/409bb2d2621680fcbebdea4fc86bf86b), and the [customer discussion](https://alien-internal.slack.com/archives/C0BSRAU8PPD/p1793394616813439).

The feedback asks for generated code inside `alien_sdk` instead of a shared top-level `baml_sdk`. The linked Slack reply from Itamar Zand also requests shared-engine and Zod work. Those latter requests are not addressed by this release. The package-name feature is a partial delivery, and adopting it in Alien's facade is separate from publishing BAML.

- [ ] Have the customer owner verify Alien's adoption and decide whether to send this scoped update to Alon/Itamar. Do not mark the shared-engine or Zod tasks complete.
- Message URL: pending.

```text
The package-name part of SDK isolation is available in BAML 0.25.0. A Python generator can use package_name = "alien_sdk._generated" so its installed files do not collide with another library's top-level baml_sdk. Go, Rust, and TypeScript can name their generated output too. This fixes the package installation collision; it does not yet give two SDKs independent programs or type maps in one process. The shared-engine and Zod requests remain separate work. Release notes and configuration examples: https://boundaryml.com/changelog.
```
