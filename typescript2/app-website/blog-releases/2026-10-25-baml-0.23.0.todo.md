# GitHub issue: https://github.com/BoundaryML/baml/issues/4765

Author: @oreoorbitz

> BAML string literals do not decode hex (`\xHH`) or unicode (`\uHHHH`) escape sequences — the backslash bytes are kept raw. They survive lexing, `Display`, `Debug`, `as_str()`, `len()`, and JSON serialization, so a literal containing a control char measures longer than the string it denotes and never equals the intended value.

- [ ] Post after publication gates pass.
- Comment URL: pending.

```text
Thank you @oreoorbitz for the string-escape report. BAML 0.23.0 includes the strict hex/Unicode escape decoding fix from #5345. Unknown escapes now produce diagnostics; use raw quoted strings or escaped backslashes where the backslash is data. The migration notes are at https://boundaryml.com/changelog.
```
